# 방어적 복사 (defensive copy)

## 한 줄 정의
가변 객체를 받거나 내줄 때 원본 대신 복사본을 저장하거나 반환해서, 클래스 밖의 코드가 내부 상태를 바꿀 수 없게 하는 기법.

## 도입 버전
- 설계 기법이라 모든 버전에 해당한다. Java 7 레거시에서도 그대로 쓸 수 있다.
- `(Java 10+)` `List.copyOf`/`Set.copyOf`/`Map.copyOf`는 불변 복사본을 만든다. 인자가 이미 불변 컬렉션이면 복사 없이 그대로 반환한다.
- `(Java 8+)` `java.time` 같은 불변 타입을 쓰면 복사 자체가 필요 없어진다.

## 무엇을 하는가
`final` 필드는 참조만 고정하므로, 필드가 가리키는 가변 객체는 두 경로로 외부에 노출된다.
- 받을 때: 생성자나 메서드 인자로 받은 객체를 그대로 저장하면, 호출자가 쥐고 있는 참조로 내부 상태를 바꿀 수 있다.
- 내줄 때: 접근자가 내부 객체를 그대로 반환하면, 받은 쪽이 내부 상태를 바꿀 수 있다.

두 경로 모두 복사본으로 막는다. 받을 때는 두 가지 순서 규칙이 있다.
- 복사를 검증보다 먼저 한다. 검증 후 복사하면, 그 사이에 다른 스레드가 원본을 바꾸는 공격(TOCTOU)에 뚫린다.
- 타입이 `final`이 아닌 인자는 `clone()`으로 복사하지 않는다. 하위 클래스가 `clone()`을 재정의해 자기 참조를 몰래 보관할 수 있다. 생성자나 정적 팩터리로 복사한다.

## 최소 사용 예
```java
public final class Period {
    private final Date start, end;

    public Period(Date start, Date end) {
        this.start = new Date(start.getTime());   // 1) 받을 때 복사 — 검증보다 먼저
        this.end   = new Date(end.getTime());
        if (this.start.after(this.end)) throw new IllegalArgumentException();  // 2) 복사본을 검증
    }
    public Date start() { return new Date(start.getTime()); }   // 3) 내줄 때 복사
}
```

## 자주 하는 오해 / 헷갈리는 짝
- **방어적 복사 vs 수정 불가 뷰** — 기준은 "원본과 연결이 끊기는가"이다. `Collections.unmodifiableList(list)`를 반환하면 받은 쪽은 수정할 수 없지만, 내부 원본이 바뀌면 그 변화가 보인다. 내부 필드를 읽기 전용으로 노출하는 데는 충분하지만, 인자로 받은 리스트를 이것만으로 감싸 저장하면 호출자가 원본을 바꿀 수 있어서 방어가 되지 않는다.
- **얕은 복사의 한계** — `new ArrayList<>(list)`는 리스트 구조만 복사하고 원소는 공유한다. 원소가 가변 객체면 원소까지 복사하거나, 원소 타입을 불변으로 만들어야 한다.
- **항상 복사해야 한다** — 비용이 드는 작업이다. 불변 타입을 쓰면 복사가 필요 없고, 같은 패키지 안의 신뢰할 수 있는 호출자라면 문서로 "수정하지 말 것"을 명시하고 생략하기도 한다.
