## 1. 예제 개요

[오프셋 페이징 예제](../오프셋페이징/오프셋페이징-예제.md)와 **같은 `post` 테이블, 같은 인덱스, 같은 테스트 데이터**(10건마다 `created_at`이 같은 1,000건)로 커서 페이징 API를 만든다. 두 문서의 결과를 나란히 비교할 수 있다.

| 검증하는 개념 | 이론 문서 | 이 문서 |
|---|---|---|
| tie-breaker 없는 커서의 누락 | 3장, 8.1 | 3장, 4 단계 1 |
| 행 값 비교 + 인덱스 Seek | 5.2, 6장 | 4 단계 1, 6.2 |
| size + 1 미리 읽기 | 3장, 5.1 | 4 단계 2, 테스트 ⑤ |
| 불투명 커서, 정밀도 보존 | 6장, 8.5 | 4 단계 3, 테스트 ⑥⑦ |
| 데이터 변경에도 중복·누락 없음 | 5.3 | 테스트 ②③ |
| 이전 페이지 (역방향) | 5.4, 8.6 | 4 단계 4, 테스트 ④ |
| Spring Data Scroll API | 6장, 10장 | 4 단계 5, 테스트 ⑧ |

## 3. 잘못된 코드 먼저

```java
@RestController
@RequestMapping("/bad/posts")
public class BadCursorController {

    private final BadPostRepository repository;

    public BadCursorController(BadPostRepository repository) {
        this.repository = repository;
    }

    // 클라이언트가 응답의 마지막 createdAt을 cursor로 다시 보낸다
    @GetMapping
    public List<Post> list(@RequestParam(required = false) LocalDateTime cursor) {
        return cursor == null
                ? repository.findTop20ByOrderByCreatedAtDesc()
                : repository.findTop20ByCreatedAtLessThanOrderByCreatedAtDesc(cursor);
    }
}

interface BadPostRepository extends JpaRepository<Post, Long> {

    List<Post> findTop20ByOrderByCreatedAtDesc();

    List<Post> findTop20ByCreatedAtLessThanOrderByCreatedAtDesc(LocalDateTime cursor);
}
```

문제점:

| 문제 | 이론 | 결과 |
|---|---|---|
| 커서가 `createdAt` 하나 | 8.1 | 20번째 행과 같은 시각인 나머지 행이 다음 페이지에서 **확정적으로** 빠진다. 이 데이터에서는 페이지마다 최대 9건 누락 |
| 클라이언트가 커서 값을 직접 만듦 | 8.5 | JSON → JavaScript `Date`를 거치면 밀리초로 잘려 마이크로초 단위 행이 누락 |
| 다음 페이지 유무를 안 알려 줌 | 5.1 | 클라이언트는 빈 배열이 올 때까지 요청한다. 마지막에 항상 불필요한 요청 1번 |
| 커서 형식이 API 계약에 노출 | 6장 | 정렬 기준을 `(createdAt, id)`로 고치는 순간 기존 클라이언트가 모두 깨진다 |
| 엔티티를 그대로 반환 | - | 내부 구조 노출, 지연 로딩 프록시 직렬화 문제 |

## 4. 개선된 코드

### 단계 1 — 유일 키셋과 행 값 비교

```sql
select * from post
where (created_at, id) < (:createdAt, :id)
order by created_at desc, id desc
limit :pageSize
```

- 좋아진 점: `(created_at, id)`는 유일하므로 동점 행이 빠지지 않는다. 인덱스 `(created_at desc, id desc)`와 컬럼 순서·방향이 같아서 조건이 `Index Cond`가 된다 (6.2).
- JPQL 파생 쿼리로는 행 값 비교를 표현하기 어려워 네이티브 쿼리를 쓴다.

### 단계 2 — size + 1 미리 읽기

```java
List<Post> rows = postRepository.findNextPage(c.createdAt(), c.id(), size + 1);
boolean hasNext = rows.size() > size;
```

- 좋아진 점: 마지막 페이지에서 `hasNext = false`를 바로 알려 준다. count 쿼리도, 빈 페이지 요청도 없다.

### 단계 3 — 불투명 커서

```java
// "v1|2026-01-01T01:39|998" → "djF8MjAyNi0wMS0wMVQwMTozOXw5OTg"
String token = Base64.getUrlEncoder().withoutPadding().encodeToString(raw.getBytes(UTF_8));
```

- 좋아진 점: 서버가 DB 값을 **정밀도 손실 없이** 인코딩한다. 클라이언트는 토큰을 그대로 돌려보내기만 하므로 커서 내부 형식을 바꿔도 API 계약이 유지된다. `v1` 접두어로 형식이 바뀌면 이전 토큰을 거절할 수 있다.
- URL-safe Base64를 쓰는 이유: 일반 Base64의 `+`, `/`, `=`는 쿼리 스트링에서 인코딩이 필요하다.

### 단계 4 — 이전 페이지

```sql
select * from post
where (created_at, id) > (:createdAt, :id)    -- 비교 반대
order by created_at asc, id asc               -- 정렬 반대
limit :pageSize
```

조회 결과를 `Collections.reverse`로 뒤집어 화면 순서(최신순)로 맞춘다.

### 단계 5 — Spring Data Scroll API (3.1+)

```java
Window<Post> findFirst20ByOrderByCreatedAtDescIdDesc(ScrollPosition position);
```

- 좋아진 점: 쿼리 없이 메서드 이름만으로 키셋 페이징이 된다.
- 한계: 크기가 메서드 이름에 고정되고, HTTP 커서로 쓰려면 `KeysetScrollPosition#getKeys()`를 직접 인코딩해야 한다. 그래서 이 예제의 API는 단계 1~4의 네이티브 쿼리 방식을 쓰고, Scroll API는 **같은 결과가 나오는지 비교**하는 데만 쓴다 (테스트 ⑧).

`post/PostCursor.java`

```java
package com.example.paging.post;

import java.nio.charset.StandardCharsets;
import java.time.LocalDateTime;
import java.time.format.DateTimeParseException;
import java.util.Base64;

/**
 * 최신순 목록의 키셋 (createdAt, id).
 * 클라이언트에는 내부 형식을 감춘 토큰으로만 내보낸다.
 */
public record PostCursor(LocalDateTime createdAt, long id) {

    // 커서 형식(정렬 키 구성)을 바꾸면 버전을 올려 이전 토큰을 명확히 거절한다
    private static final String VERSION = "v1";
    private static final String DELIMITER = "|";

    public static PostCursor of(Post post) {
        return new PostCursor(post.getCreatedAt(), post.getId());
    }

    public String encode() {
        // LocalDateTime#toString은 나노초 필드를 잘라내지 않고 출력한다.
        // 밀리초 포맷 등으로 정밀도를 깎으면 그 사이의 행이 누락된다 (이론 8.5)
        String raw = VERSION + DELIMITER + createdAt + DELIMITER + id;
        return Base64.getUrlEncoder().withoutPadding()
                .encodeToString(raw.getBytes(StandardCharsets.UTF_8));
    }

    public static PostCursor decode(String token) {
        String[] parts;
        try {
            String raw = new String(Base64.getUrlDecoder().decode(token), StandardCharsets.UTF_8);
            parts = raw.split("\\|");
        } catch (IllegalArgumentException e) {   // Base64 형식 오류
            throw new InvalidCursorException(token, e);
        }
        if (parts.length != 3 || !VERSION.equals(parts[0])) {
            throw new InvalidCursorException(token);
        }
        try {
            return new PostCursor(LocalDateTime.parse(parts[1]), Long.parseLong(parts[2]));
        } catch (DateTimeParseException | NumberFormatException e) {
            throw new InvalidCursorException(token, e);
        }
    }
}
```

```java
package com.example.paging.post;

import org.springframework.data.domain.ScrollPosition;
import org.springframework.data.domain.Window;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.time.LocalDateTime;
import java.util.List;

public interface PostRepository extends JpaRepository<Post, Long> {

    @Query(value = """
            select * from post
            order by created_at desc, id desc
            limit :pageSize
            """, nativeQuery = true)
    List<Post> findFirstPage(@Param("pageSize") int pageSize);

    // 행 값 비교가 인덱스 (created_at desc, id desc)의 탐색 시작점이 된다
    @Query(value = """
            select * from post
            where (created_at, id) < (:createdAt, :id)
            order by created_at desc, id desc
            limit :pageSize
            """, nativeQuery = true)
    List<Post> findNextPage(@Param("createdAt") LocalDateTime createdAt,
                            @Param("id") long id,
                            @Param("pageSize") int pageSize);

    // 커서 바로 앞쪽부터 읽으려면 비교와 정렬을 함께 뒤집어야 한다. 결과는 서비스에서 다시 뒤집는다
    @Query(value = """
            select * from post
            where (created_at, id) > (:createdAt, :id)
            order by created_at asc, id asc
            limit :pageSize
            """, nativeQuery = true)
    List<Post> findPrevPage(@Param("createdAt") LocalDateTime createdAt,
                            @Param("id") long id,
                            @Param("pageSize") int pageSize);

    // Spring Data 3.1+ Scroll API. 네이티브 구현과 결과를 비교하는 용도
    Window<Post> findFirst20ByOrderByCreatedAtDescIdDesc(ScrollPosition position);
}
```

### 5.5 서비스와 컨트롤러

`post/PostCursorService.java`

```java
package com.example.paging.post;

import com.example.paging.common.CursorResponse;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

@Service
@Transactional(readOnly = true)
public class PostCursorService {

    static final int MAX_SIZE = 100;

    private final PostRepository postRepository;

    public PostCursorService(PostRepository postRepository) {
        this.postRepository = postRepository;
    }

    /** cursor가 null이면 첫 페이지. */
    public CursorResponse<PostDto> getNext(String cursor, int size) {
        int safeSize = clamp(size);
        List<Post> rows;
        if (cursor == null) {
            rows = postRepository.findFirstPage(safeSize + 1);
        } else {
            PostCursor c = PostCursor.decode(cursor);
            rows = postRepository.findNextPage(c.createdAt(), c.id(), safeSize + 1);
        }

        boolean hasNext = rows.size() > safeSize;
        List<Post> content = hasNext ? rows.subList(0, safeSize) : rows;

        String nextCursor = hasNext ? encodeLast(content) : null;
        // 커서를 받아 왔다면 앞 페이지가 있다. 결과가 비었으면 받은 커서가 곧 이전 페이지의 기준이다
        String prevCursor = cursor == null ? null
                : content.isEmpty() ? cursor : encodeFirst(content);
        return CursorResponse.of(toDtos(content), nextCursor, prevCursor);
    }

    public CursorResponse<PostDto> getPrev(String cursor, int size) {
        int safeSize = clamp(size);
        PostCursor c = PostCursor.decode(cursor);
        List<Post> rows = postRepository.findPrevPage(c.createdAt(), c.id(), safeSize + 1);

        boolean hasPrev = rows.size() > safeSize;
        List<Post> content = new ArrayList<>(hasPrev ? rows.subList(0, safeSize) : rows);
        // 오래된 순(ASC)으로 읽었으므로 화면 순서(최신순)로 되돌린다 (이론 8.6)
        Collections.reverse(content);

        String prevCursor = hasPrev ? encodeFirst(content) : null;
        String nextCursor = content.isEmpty() ? cursor : encodeLast(content);
        return CursorResponse.of(toDtos(content), nextCursor, prevCursor);
    }

    private int clamp(int size) {
        return Math.max(1, Math.min(size, MAX_SIZE));
    }

    private String encodeFirst(List<Post> content) {
        return PostCursor.of(content.get(0)).encode();
    }

    private String encodeLast(List<Post> content) {
        return PostCursor.of(content.get(content.size() - 1)).encode();
    }

    private List<PostDto> toDtos(List<Post> content) {
        return content.stream().map(PostDto::from).toList();
    }
}
```

`post/PostCursorController.java`

```java
package com.example.paging.post;

import com.example.paging.common.CursorResponse;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

@RestController
@RequestMapping("/posts")
public class PostCursorController {

    private final PostCursorService postCursorService;

    public PostCursorController(PostCursorService postCursorService) {
        this.postCursorService = postCursorService;
    }

    @GetMapping
    public CursorResponse<PostDto> next(@RequestParam(required = false) String cursor,
                                        @RequestParam(defaultValue = "20") int size) {
        return postCursorService.getNext(cursor, size);
    }

    @GetMapping("/prev")
    public CursorResponse<PostDto> prev(@RequestParam String cursor,
                                        @RequestParam(defaultValue = "20") int size) {
        return postCursorService.getPrev(cursor, size);
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, String>> badRequest(IllegalArgumentException e) {
        return ResponseEntity.badRequest().body(Map.of("message", e.getMessage()));
    }
}
```

`common/CursorResponse.java`

```java
package com.example.paging.common;

import java.util.List;

/**
 * 커서는 null이면 그 방향에 더 이상 페이지가 없다는 뜻이다.
 * hasNext/hasPrev는 클라이언트 편의를 위해 커서에서 계산해 함께 내보낸다.
 */
public record CursorResponse<T>(List<T> content, String nextCursor, String prevCursor,
                                boolean hasNext, boolean hasPrev) {

    public static <T> CursorResponse<T> of(List<T> content, String nextCursor, String prevCursor) {
        return new CursorResponse<>(content, nextCursor, prevCursor,
                nextCursor != null, prevCursor != null);
    }
}
```

### 5.6 Java 8 대응 코드

Spring Boot 3.x는 Java 17 이상이 필요하다. Java 8 코드베이스(Spring Boot 2.x, `javax.persistence`)에서도 **네이티브 쿼리 방식은 그대로 동작**한다. Scroll API(`Window`, `ScrollPosition`)만 Spring Data 3.1+ 전용이다.

| Java 21 코드 | Java 8 대응 |
|---|---|
| `jakarta.persistence.*` | `javax.persistence.*` |
| `record PostCursor`, `record CursorResponse` | 아래 클래스 |
| 텍스트 블록 `"""` | 문자열 연결 |
| `stream().toList()` | `collect(Collectors.toList())` |
| `Map.of(...)` | `Collections.singletonMap(...)` |
| `Window` 메서드 | 삭제 |

```java
package com.example.paging.post;

import java.nio.charset.StandardCharsets;
import java.time.LocalDateTime;
import java.time.format.DateTimeParseException;
import java.util.Base64;
import java.util.Objects;

public final class PostCursor {

    private static final String VERSION = "v1";
    private static final String DELIMITER = "|";

    private final LocalDateTime createdAt;
    private final long id;

    public PostCursor(LocalDateTime createdAt, long id) {
        this.createdAt = Objects.requireNonNull(createdAt);
        this.id = id;
    }

    public static PostCursor of(Post post) {
        return new PostCursor(post.getCreatedAt(), post.getId());
    }

    public String encode() {
        String raw = VERSION + DELIMITER + createdAt + DELIMITER + id;
        return Base64.getUrlEncoder().withoutPadding()
                .encodeToString(raw.getBytes(StandardCharsets.UTF_8));
    }

    public static PostCursor decode(String token) {
        String[] parts;
        try {
            String raw = new String(Base64.getUrlDecoder().decode(token), StandardCharsets.UTF_8);
            parts = raw.split("\\|");
        } catch (IllegalArgumentException e) {
            throw new InvalidCursorException(token, e);
        }
        if (parts.length != 3 || !VERSION.equals(parts[0])) {
            throw new InvalidCursorException(token);
        }
        try {
            return new PostCursor(LocalDateTime.parse(parts[1]), Long.parseLong(parts[2]));
        } catch (DateTimeParseException | NumberFormatException e) {
            throw new InvalidCursorException(token, e);
        }
    }

    public LocalDateTime createdAt() { return createdAt; }
    public long id() { return id; }

    // record가 자동 생성하던 equals/hashCode를 직접 구현한다
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof PostCursor)) return false;
        PostCursor that = (PostCursor) o;
        return id == that.id && createdAt.equals(that.createdAt);
    }

    @Override
    public int hashCode() {
        return Objects.hash(createdAt, id);
    }
}
```

```sql
insert into post (title, created_at)
select 'post-' || g, timestamp '2026-01-01' + (g / 10) * interval '1 minute'
from generate_series(1, 1000000) g;
vacuum analyze post;

explain (analyze, buffers)
select * from post
where (created_at, id) < ('2026-01-07 22:40:00', 100001)
order by created_at desc, id desc
limit 21;
```

```text
Limit  (actual time=0.03..0.05 rows=21 loops=1)
  Buffers: shared hit=5
  ->  Index Scan using idx_post_created_at_id on post  (actual time=0.03..0.04 rows=21 loops=1)

        Buffers: shared hit=5
Execution Time: 0.07 ms
```

| 방식 | 읽은 행 | 실행 시간 (예상) |
|---|---|---|
| `OFFSET 900000` | 900,020 | ~180 ms |
| 지연 조인 | 900,020 (인덱스만) | ~95 ms |
| **커서** | **21** | **~0.1 ms** |

관찰 포인트:
- 조건이 `Filter`가 아니라 **`Index Cond`**에 있다. 인덱스 탐색 시작점으로 쓰였다는 뜻이다.
- `rows=21`, `Buffers: shared hit=5` — B-Tree 높이만큼의 페이지와 리프 몇 개만 읽었다. 커서가 첫 페이지 근처든 마지막 근처든 같다.

```java
        String cursor = null;
        do {
```

테스트 설계 메모:
- 테스트 이름의 `t1_`~`t8_`은 1장 표의 테스트 ①~⑧과 대응한다.
- `@DataJpaTest`는 테스트마다 롤백하므로 `setUp`의 1,000건이 매번 새로 들어간다. `bigserial`은 롤백돼도 값이 돌아오지 않으므로 **id 값 자체는 단언하지 않고** baseline과 비교한다.
- t2·t3·t6에서 `em.flush()`를 명시한 이유: 네이티브 쿼리 실행 전 자동 flush 범위는 Hibernate 버전·설정에 따라 다를 수 있다. 테스트가 그 동작에 의존하지 않게 한다.
- t2·t3는 [오프셋 예제의 테스트 ②](../오프셋페이징/오프셋페이징-예제.md#7-검증-코드)와 같은 시나리오다. 오프셋에서는 중복이 생겼고, 커서에서는 baseline과 정확히 같다.
- t6의 PostgreSQL `timestamp` 정밀도는 마이크로초다. `LocalDateTime`의 나노초 중 마이크로초 아래 자리는 저장 시 반올림되므로, 테스트 값은 마이크로초 단위로 맞췄다.

## 8. 변형 실습

### 실습 1 — 정렬 방향이 섞이면?

인덱스를 `(created_at desc, id asc)`로 바꾸고, 정렬을 `order by created_at desc, id asc`로 바꾼다. 커서 조건은 그대로 `(created_at, id) < (?, ?)`로 둔 채 t1을 실행한다.

- 예상: 같은 `created_at` 그룹 안에서 커서보다 **id가 큰** 행(다음에 나와야 할 행)이 조건에서 빠져 누락이 생긴다 (이론 8.2).
- 고치기: `created_at <= :createdAt and (created_at < :createdAt or id > :id)`로 바꾸고 `EXPLAIN`에서 `Index Cond`에 `created_at <= ...`가 들어가는지 확인한다.

### 실습 2 — 필터 컬럼이 인덱스에 없으면?

`post`에 `board_id bigint not null` 컬럼을 추가하고 1~10을 고르게 넣는다. `where board_id = 3 and (created_at, id) < (?, ?)`로 조회하며 두 인덱스를 비교한다.

```sql
create index idx_a on post (created_at desc, id desc);              -- 필터 컬럼 없음
create index idx_b on post (board_id, created_at desc, id desc);    -- 필터 컬럼 선두
```

- 예상: `idx_a`만 있으면 `board_id = 3`이 `Filter`로 나와 다른 게시판 행을 읽고 버린다(`Rows Removed by Filter`). `idx_b`가 있으면 두 조건이 모두 `Index Cond`가 된다.
- 생각해 볼 것: 게시판 3의 글이 전체의 0.1%뿐이라면 `idx_a`의 비용은 어떻게 변하는가?

### 실습 3 — 정렬 옵션 추가와 커서 위조 방지

`OLDEST` 정렬을 추가하고, 커서 형식을 `v2|정렬|createdAt|id|서명`으로 바꾼다. 서명은 `HmacSHA256(서버 비밀키, "v2|정렬|createdAt|id")`로 만든다.

- 확인할 것 ①: `LATEST`로 받은 커서를 `OLDEST` 요청에 넣으면 400이 나는가? (이론 8.3)
- 확인할 것 ②: 토큰 안의 id만 바꿔 다시 인코딩하면 서명 검증에서 거절되는가?
- 확인할 것 ③: `v1` 토큰이 들어오면 명확한 메시지로 거절되는가? 배포 직후 클라이언트가 들고 있던 커서는 어떻게 처리할지(거절 후 첫 페이지 재요청 / 일정 기간 v1 호환) 정책을 정해 본다.
