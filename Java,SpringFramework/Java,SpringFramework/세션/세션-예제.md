# 서버 세션 — 예제

관련 문서: [이론](./세션-이론.md) · [쿠키](../쿠키/쿠키-이론.md) · [분산 세션](../분산세션/분산세션-이론.md)

---

## 1. 예제 개요

React SPA가 호출하는 형태의 **REST 로그인 API**를 Spring Security 6 위에 만든다. 먼저 Spring Boot 2 시절 코드를 그대로 옮긴 로그인과 세션 장바구니가 어떻게 깨지는지 보고, 단계적으로 고친다.

| 검증할 개념 | 이론 문서 대응 | 확인 방법 |
|---|---|---|
| 세션은 `getSession()` 호출 시점에 생긴다. `getSession(false)`는 만들지 않는다 | [3장](./세션-이론.md#3-최소-예제로-보기), 6.2 | 요청 후 세션 존재 여부, `Set-Cookie` 유무 |
| Spring Security 6은 SecurityContext를 자동 저장하지 않는다 | 6.4, 함정 1 | 잘못된 로그인 → 다음 요청 401 |
| 직접 작성한 로그인은 세션 고정 방어를 받지 못한다 | 6.3, 함정 2 | 로그인 전후 세션 ID 비교 |
| 세션 속성 안의 가변 객체는 동시 요청에 안전하지 않다 | 6.1, 함정 3 | 같은 세션으로 동시 200건 추가 |
| 로그아웃은 세션을 무효화한다 | 5.1-7 | 로그아웃 후 같은 쿠키로 요청 → 401 |

## 3. 잘못된 코드 먼저

### 3.1 Spring Boot 2(Security 5)에서 옮겨온 로그인 컨트롤러

```java
@PostMapping("/api/bad/login")
public ResponseEntity<String> login(@RequestBody LoginRequest body) {
    Authentication auth = authenticationManager.authenticate(
            UsernamePasswordAuthenticationToken.unauthenticated(body.username(), body.password()));
    SecurityContextHolder.getContext().setAuthentication(auth);   // Security 5에서는 이것으로 충분했다
    return ResponseEntity.ok(auth.getName());
}
```

| 문제 | 실제로 생기는 일 | 이론 문서 |
|---|---|---|
| 저장 누락 | `SecurityContextHolder`는 ThreadLocal이라 요청이 끝나면 비워진다. Security 6은 세션에 자동 저장하지 않으므로 다음 요청 `GET /api/me`가 **401** | 함정 1 |
| ID 미변경 | 로그인 전 세션이 있었다면 로그인 후에도 **같은 ID**. 세션 고정 공격에 노출 | 함정 2 |

### 3.2 세션 장바구니

```java
@PostMapping("/cart/bad/add")
public int add(@RequestParam String item, HttpSession session) {
    List<String> cart = (List<String>) session.getAttribute("cart");
    if (cart == null) {
        cart = new ArrayList<>();
        session.setAttribute("cart", cart);
    }
    cart.add(item);           // 여러 요청 스레드가 같은 ArrayList를 동시에 수정한다
    return cart.size();
}
```

| 문제 | 실제로 생기는 일 | 이론 문서 |
|---|---|---|
| 가변 객체 공유 | 동시 요청 200건 중 일부가 사라지거나, 드물게 `ArrayIndexOutOfBoundsException`으로 500 | 함정 3 |
| `cart == null` 검사 경쟁 | 첫 요청 두 개가 동시에 오면 둘 다 새 리스트를 만들고 하나가 덮어쓴다 | 함정 3 |

## 4. 개선된 코드 (단계적으로)

### 4.1 1단계 — SecurityContext를 명시적으로 저장한다

```java
SecurityContext context = securityContextHolderStrategy.createEmptyContext();
context.setAuthentication(auth);
securityContextHolderStrategy.setContext(context);
securityContextRepository.saveContext(context, request, response);
```

**좋아진 점**: 인증 정보가 세션 속성 `SPRING_SECURITY_CONTEXT`에 들어가므로 다음 요청에서 `SecurityContextHolderFilter`가 복원한다.
`securityContextRepository`는 `SecurityConfig`에서 필터 체인에 등록한 것과 **같은 빈**을 주입받는다. 다른 인스턴스·다른 구현(예: `RequestAttributeSecurityContextRepository`)을 쓰면 저장 위치가 어긋나 같은 증상이 재발한다.

### 4.2 2단계 — 저장 전에 세션 ID를 바꾼다

```java
sessionAuthenticationStrategy.onAuthentication(auth, request, response);  // 내부에서 request.changeSessionId()
// 그다음 1단계의 saveContext
```

**좋아진 점**: 로그인 전 세션 ID는 무효가 되고 새 ID가 `Set-Cookie`로 나간다. 속성(로그인 전 장바구니 등)은 유지된다. 폼 로그인 필터가 하던 일을 컨트롤러에서 똑같이 수행한다.

### 4.3 3단계 — 세션에는 불변 객체를 두고, 교체는 세션 단위로 직렬화한다

```java
synchronized (WebUtils.getSessionMutex(session)) {
    List<String> current = (List<String>) session.getAttribute(CART);
    List<String> next = new ArrayList<>(current == null ? List.of() : current);
    next.add(item);
    session.setAttribute(CART, List.copyOf(next));
}
```

**좋아진 점**

- 세션에 들어간 리스트는 `List.copyOf`로 만든 **불변 리스트**다. 다른 코드가 꺼내서 실수로 수정하면 `UnsupportedOperationException`이 나므로 문제가 바로 드러난다.
- "읽기 → 새 리스트 → 교체"를 세션 뮤텍스로 묶어 같은 사용자의 동시 요청을 줄 세운다. 다른 사용자끼리는 서로 막지 않는다.
- 변경 시 항상 `setAttribute`를 호출하는 습관은 [분산 세션](../분산세션/분산세션-이론.md)으로 옮겨도 그대로 맞는 코드다. (단, 세션 뮤텍스는 JVM 하나 안에서만 유효하다)
- `WebUtils.getSessionMutex`는 `HttpSessionMutexListener`가 등록되어 있으면 세션 생성 시 넣어둔 전용 뮤텍스 객체를, 없으면 세션 객체 자신을 돌려준다. 세션 래퍼 객체가 요청마다 달라질 수 있는 환경을 대비해 리스너를 등록한다.

### 4.4 4단계 — 로그아웃과 세션 쿠키 설정을 정리한다

```java
.logout(logout -> logout
        .logoutUrl("/api/logout")
        .invalidateHttpSession(true)            // 기본값이지만 의도를 드러내기 위해 명시
        .deleteCookies("JSESSIONID")
        .logoutSuccessHandler(new HttpStatusReturningLogoutSuccessHandler(HttpStatus.NO_CONTENT)))
```

```properties
server.servlet.session.tracking-modes=cookie
server.servlet.session.cookie.same-site=lax
```

**좋아진 점**: 서버 쪽 세션은 무효화되고, 브라우저 쪽 쿠키도 삭제된다. URL 재작성(`;jsessionid=`)을 끄고 SameSite를 명시한다.

### 4.5 하위 버전 대응 (Java 8 / Spring Security 5 / javax)

```java
// Java 8: record 대신 일반 클래스. Jackson 역직렬화를 위해 기본 생성자와 setter(또는 @JsonCreator)가 필요하다
public class LoginRequest {
    private String username;
    private String password;

    public LoginRequest() {
    }

    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
}
```

```java
// Java 8: List.of / List.copyOf 대신
List<String> next = new ArrayList<>(current == null ? Collections.<String>emptyList() : current);
next.add(item);
session.setAttribute(CART, Collections.unmodifiableList(next));
```

- Spring Security 5.x: `SecurityContextPersistenceFilter`가 요청 종료 시 자동 저장하므로 3.1 코드가 "동작은" 한다. 그래도 세션 고정 방어는 별도로 필요하다(`request.changeSessionId()`).
- Servlet 3.0 이하(Tomcat 7): `changeSessionId()`가 없다. `SessionFixationProtectionStrategy`(새 세션 생성 + 속성 복사)를 쓴다.
- `jakarta.servlet.*` → `javax.servlet.*`로 import를 바꾼다.

### `config/SecurityConfig.java`

```java
package com.example.session.config;

import org.springframework.boot.web.servlet.ServletListenerRegistrationBean;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpStatus;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.HttpStatusEntryPoint;
import org.springframework.security.web.authentication.logout.HttpStatusReturningLogoutSuccessHandler;
import org.springframework.security.web.authentication.session.ChangeSessionIdAuthenticationStrategy;
import org.springframework.security.web.authentication.session.SessionAuthenticationStrategy;
import org.springframework.security.web.context.HttpSessionSecurityContextRepository;
import org.springframework.security.web.context.SecurityContextRepository;
import org.springframework.web.util.HttpSessionMutexListener;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http,
                                                   SecurityContextRepository securityContextRepository)
            throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                    .requestMatchers("/api/login", "/api/bad/login").permitAll()
                    .requestMatchers("/visit", "/peek", "/bad/peek", "/cart/**").permitAll()
                    .anyRequest().authenticated())
            // 필터 체인과 로그인 컨트롤러가 같은 저장소 인스턴스를 쓰도록 빈을 주입해 등록한다
            .securityContext(ctx -> ctx.securityContextRepository(securityContextRepository))
            .sessionManagement(session -> session
                    .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
                    .sessionFixation(fixation -> fixation.changeSessionId()))
            // SPA용 REST API: 로그인 페이지로 리다이렉트하지 않고 401만 돌려준다
            .exceptionHandling(ex -> ex.authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED)))
            .logout(logout -> logout
                    .logoutUrl("/api/logout")
                    .invalidateHttpSession(true)
                    .deleteCookies("JSESSIONID")
                    .logoutSuccessHandler(new HttpStatusReturningLogoutSuccessHandler(HttpStatus.NO_CONTENT)))
            // 학습 범위를 세션으로 좁히기 위해 끈다.
            // 쿠키 세션 인증을 쓰는 실무 코드에서는 반드시 켠다 (쿠키 이론 문서 함정 5)
            .csrf(AbstractHttpConfigurer::disable);
        return http.build();
    }

    @Bean
    public SecurityContextRepository securityContextRepository() {
        return new HttpSessionSecurityContextRepository();
    }

    // 폼 로그인 필터가 내부에서 쓰는 것과 같은 전략. 직접 만든 로그인 컨트롤러가 호출한다
    @Bean
    public SessionAuthenticationStrategy sessionAuthenticationStrategy() {
        return new ChangeSessionIdAuthenticationStrategy();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration configuration) throws Exception {
        return configuration.getAuthenticationManager();
    }

    @Bean
    public UserDetailsService userDetailsService() {
        // {noop}: 학습용 평문 비밀번호. 운영에서는 {bcrypt} 등 해시 인코더를 쓴다
        return new InMemoryUserDetailsManager(
                User.withUsername("user").password("{noop}pass").roles("USER").build());
    }

    // 세션 생성 시 전용 뮤텍스 객체를 세션 속성에 넣는다 (WebUtils.getSessionMutex가 사용)
    @Bean
    public ServletListenerRegistrationBean<HttpSessionMutexListener> httpSessionMutexListener() {
        return new ServletListenerRegistrationBean<>(new HttpSessionMutexListener());
    }
}
```

```java
package com.example.session.web;

import org.springframework.http.ResponseEntity;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;

import org.springframework.web.bind.annotation.RestController;

@RestController

    private final AuthenticationManager authenticationManager;

    public BadLoginController(AuthenticationManager authenticationManager) {
        this.authenticationManager = authenticationManager;

    public ResponseEntity<String> login(@RequestBody LoginRequest body) {
        Authentication auth = authenticationManager.authenticate(
                UsernamePasswordAuthenticationToken.unauthenticated(body.username(), body.password()));
```

### `web/LoginController.java`

```java
package com.example.session.web;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.AuthenticationException;
import org.springframework.security.core.context.SecurityContext;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.context.SecurityContextHolderStrategy;
import org.springframework.security.web.authentication.session.SessionAuthenticationStrategy;
import org.springframework.security.web.context.SecurityContextRepository;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class LoginController {

    private final AuthenticationManager authenticationManager;
    private final SessionAuthenticationStrategy sessionAuthenticationStrategy;
    private final SecurityContextRepository securityContextRepository;
    // 정적 호출 대신 전략 객체를 통해 다룬다. 커스텀 홀더 전략을 쓰는 환경에서도 같은 곳에 쓰기 위함
    private final SecurityContextHolderStrategy securityContextHolderStrategy =
            SecurityContextHolder.getContextHolderStrategy();

    public LoginController(AuthenticationManager authenticationManager,
                           SessionAuthenticationStrategy sessionAuthenticationStrategy,
                           SecurityContextRepository securityContextRepository) {
        this.authenticationManager = authenticationManager;
        this.sessionAuthenticationStrategy = sessionAuthenticationStrategy;
        this.securityContextRepository = securityContextRepository;
    }

    @PostMapping("/api/login")
    public ResponseEntity<String> login(@RequestBody LoginRequest body,
                                        HttpServletRequest request,
                                        HttpServletResponse response) {
        Authentication auth;
        try {
            auth = authenticationManager.authenticate(
                    UsernamePasswordAuthenticationToken.unauthenticated(body.username(), body.password()));
        } catch (AuthenticationException e) {
            return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body("bad credentials");
        }

        // 1) 세션 고정 방어: 로그인 전 세션이 있으면 ID만 교체한다 (속성은 유지)
        sessionAuthenticationStrategy.onAuthentication(auth, request, response);

        // 2) 인증 정보를 세션에 저장한다. Security 6은 이 호출이 없으면 다음 요청에서 익명이 된다
        SecurityContext context = securityContextHolderStrategy.createEmptyContext();
        context.setAuthentication(auth);
        securityContextHolderStrategy.setContext(context);
        securityContextRepository.saveContext(context, request, response);

        return ResponseEntity.ok(auth.getName());
    }
}
```

### `web/VisitController.java`

```java
package com.example.session.web;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpSession;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class VisitController {

    @GetMapping("/visit")
    public String visit(HttpServletRequest request) {
        HttpSession session = request.getSession();
        Integer count = (Integer) session.getAttribute("count");
        count = (count == null) ? 1 : count + 1;
        // Integer는 불변이므로 매번 새 값으로 교체된다. 함정 3과 무관하다
        session.setAttribute("count", count);
        return "id=" + session.getId() + ", count=" + count + ", new=" + session.isNew();
    }

    // 조회 전용: 세션을 만들지 않는다
    @GetMapping("/peek")
    public String peek(HttpServletRequest request) {
        HttpSession session = request.getSession(false);
        return session == null ? "no session" : "count=" + session.getAttribute("count");
    }

    // 잘못된 조회: 읽기만 하려는데 습관적으로 getSession()을 호출해 세션을 만든다 (함정 4)
    @GetMapping("/bad/peek")
    public String badPeek(HttpServletRequest request) {
        Object count = request.getSession().getAttribute("count");
        return count == null ? "no count" : "count=" + count;
    }
}
```

### `web/CartController.java`

```java
package com.example.session.web;

import jakarta.servlet.http.HttpSession;
import java.util.ArrayList;
import java.util.List;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.util.WebUtils;

@RestController
public class CartController {

    private static final String CART = "cart";
    private static final String BAD_CART = "badCart";

    @PostMapping("/cart/bad/add")
    @SuppressWarnings("unchecked")
    public int badAdd(@RequestParam String item, HttpSession session) {
        List<String> cart = (List<String>) session.getAttribute(BAD_CART);
        if (cart == null) {
            cart = new ArrayList<>();
            session.setAttribute(BAD_CART, cart);
        }
        cart.add(item);
        return cart.size();
    }

    @GetMapping("/cart/bad")
    @SuppressWarnings("unchecked")
    public int badSize(HttpSession session) {
        List<String> cart = (List<String>) session.getAttribute(BAD_CART);
        return cart == null ? 0 : cart.size();
    }

    @PostMapping("/cart/add")
    @SuppressWarnings("unchecked")
    public int add(@RequestParam String item, HttpSession session) {
        // 같은 세션(같은 사용자)의 요청만 줄 세운다. 다른 사용자는 서로 막지 않는다
        synchronized (WebUtils.getSessionMutex(session)) {
            List<String> current = (List<String>) session.getAttribute(CART);
            List<String> next = new ArrayList<>(current == null ? List.of() : current);
            next.add(item);
            // 불변 리스트로 교체: 다른 코드가 꺼내서 수정하는 실수를 즉시 예외로 드러낸다
            List<String> frozen = List.copyOf(next);
            session.setAttribute(CART, frozen);
            return frozen.size();
        }
    }

    @GetMapping("/cart")
    @SuppressWarnings("unchecked")
    public List<String> cart(HttpSession session) {
        List<String> cart = (List<String>) session.getAttribute(CART);
        return cart == null ? List.of() : cart;
    }
}
```

```java
                .andExpect(status().isOk());

    @DisplayName("개선: saveContext로 저장하면 다음 요청에서 인증이 복원된다")

        MockHttpSession session = new MockHttpSession();

        mockMvc.perform(post("/api/login").session(session)
                        .contentType(MediaType.APPLICATION_JSON).content(LOGIN_JSON))
                .andExpect(status().isOk());

        assertThat(session.getAttribute(
                HttpSessionSecurityContextRepository.SPRING_SECURITY_CONTEXT_KEY)).isNotNull();

                .andExpect(status().isOk())

    void sessionFixationProtection() throws Exception {

        mockMvc.perform(get("/visit").session(badSession));

        mockMvc.perform(post("/api/bad/login").session(badSession)
```

### 7.2 실제 Tomcat — 세션 쿠키와 동시성

```java
package com.example.session;

import static org.assertj.core.api.Assertions.assertThat;

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.CompletableFuture;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.web.server.LocalServerPort;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class SessionRealTomcatTest {

    private static final int REQUESTS = 200;

    @LocalServerPort
    int port;

    private final HttpClient client = HttpClient.newHttpClient();

    private URI uri(String path) {
        return URI.create("http://localhost:" + port + path);
    }

    // 브라우저처럼 Set-Cookie에서 "JSESSIONID=..." 부분만 꺼낸다. 속성은 서버로 다시 보내지 않는다
    private String newSessionCookie() throws Exception {
        HttpResponse<String> response = client.send(
                HttpRequest.newBuilder(uri("/visit")).GET().build(),
                HttpResponse.BodyHandlers.ofString());
        String setCookie = response.headers().firstValue("Set-Cookie").orElseThrow();
        return setCookie.substring(0, setCookie.indexOf(';'));
    }

    @Test
    @DisplayName("Tomcat 세션 쿠키는 Path=/, HttpOnly, SameSite=Lax로 나간다")
    void sessionCookieAttributes() throws Exception {
        HttpResponse<String> response = client.send(
                HttpRequest.newBuilder(uri("/visit")).GET().build(),
                HttpResponse.BodyHandlers.ofString());

        String setCookie = response.headers().firstValue("Set-Cookie").orElseThrow();
        assertThat(setCookie).startsWith("JSESSIONID=")
                .contains("Path=/", "HttpOnly", "SameSite=Lax");
        // Tomcat 기본 세션 ID: 16바이트 → 16진수 32자
        String id = setCookie.substring("JSESSIONID=".length(), setCookie.indexOf(';'));
        assertThat(id).hasSize(32);
    }

    @Test
    @DisplayName("같은 세션으로 동시 200건: 불변 교체 + 세션 뮤텍스는 항상 200")
    void concurrentCartAdds() throws Exception {
        String badCookie = newSessionCookie();
        String goodCookie = newSessionCookie();

        fireConcurrently("/cart/bad/add", badCookie);
        fireConcurrently("/cart/add", goodCookie);

        int badSize = Integer.parseInt(get("/cart/bad", badCookie));
        String goodBody = get("/cart", goodCookie);
        int goodSize = goodBody.equals("[]") ? 0 : goodBody.split(",").length;

        System.out.println("bad cart size after " + REQUESTS + " concurrent adds = " + badSize);
        System.out.println("good cart size after " + REQUESTS + " concurrent adds = " + goodSize);

        // 잘못된 코드는 결과가 비결정적이라 단언하지 않는다. 200 이하라는 것만 확인한다
        assertThat(badSize).isLessThanOrEqualTo(REQUESTS);
        assertThat(goodSize).isEqualTo(REQUESTS);
    }

    private void fireConcurrently(String path, String cookie) {
        List<CompletableFuture<HttpResponse<String>>> futures = new ArrayList<>();
        for (int i = 0; i < REQUESTS; i++) {
            HttpRequest request = HttpRequest.newBuilder(uri(path + "?item=i" + i))
                    .header("Cookie", cookie)
                    .POST(HttpRequest.BodyPublishers.noBody())
                    .build();
            futures.add(client.sendAsync(request, HttpResponse.BodyHandlers.ofString()));
        }
        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
    }

    private String get(String path, String cookie) throws Exception {
        return client.send(
                HttpRequest.newBuilder(uri(path)).header("Cookie", cookie).GET().build(),
                HttpResponse.BodyHandlers.ofString()).body();
    }
}
```

## 8. 변형 실습

1. **`SecurityConfig`에서 `HttpStatusEntryPoint`를 빼고 `GET /api/me`를 비로그인으로 호출하면?**
   기본 진입점이 로그인 페이지 리다이렉트(또는 기본 폼 로그인 미구성 시 403/401)로 바뀐다. 더 중요한 것은 이 과정에서 `HttpSessionRequestCache`가 "로그인 후 돌아갈 요청"을 저장하려고 **세션을 만든다**는 점이다. `Set-Cookie: JSESSIONID`가 생기는지 확인해 보라. (`Accept: application/json` 헤더를 붙이면 기본 요청 캐시 매처가 저장을 건너뛴다. 확인 필요: 버전별 기본 매처 조건) 보호된 API를 봇이 두드리면 함정 4가 생기는 경로다. `http.requestCache(cache -> cache.disable())`로 끄고 다시 확인한다.

2. **`VisitController#visit`에 `session.setMaxInactiveInterval(5)`를 넣고, 10초 뒤 같은 쿠키로 `/peek`를 호출하면?**
   `no session`이 나온다. 조회 시점에 만료 판정이 일어나기 때문이다. 이번에는 `HttpSessionListener` 빈을 등록해 `sessionDestroyed`에 로그를 찍고, **요청을 보내지 않고** 기다려 보라. 로그는 5초가 아니라 Tomcat 백그라운드 주기(약 60초)에 맞춰 늦게 찍힌다. ([이론 6.5](./세션-이론.md#6-내부-구현-핵심만))

3. **`LoginController`에서 `sessionAuthenticationStrategy.onAuthentication(...)` 호출을 `saveContext(...)` 뒤로 옮기면?**
   `ChangeSessionIdAuthenticationStrategy`는 같은 세션 객체의 ID만 바꾸므로 테스트는 여전히 통과한다. 그런데 `SessionFixationProtectionStrategy`(새 세션을 만들고 속성을 복사하는 방식, `sessionFixation().migrateSession()`)로 바꾸면 어떻게 될까? 복사 대상에 이미 저장한 `SPRING_SECURITY_CONTEXT`가 포함되는지, 옛 세션은 언제 무효화되는지 직접 확인해 보고 "ID 변경 → 저장" 순서가 안전한 이유를 설명해 본다.
