## 1. 예제 개요

로그인 토큰 쿠키와 닉네임 쿠키를 굽는 작은 Spring Boot API를 만든다. 먼저 실무에서 흔히 보는 잘못된 코드(`BadCookieController`)를 실행해 문제를 확인하고, 쿠키 생성 규칙을 한 곳에 모은 코드(`AuthCookieManager`, `GoodCookieController`)로 고친다.

| 검증할 개념 | 이론 문서 대응 | 확인 방법 |
|---|---|---|
| 서버로는 이름=값만 돌아오고 속성은 사라진다 | [5.1, 6.1](./쿠키-이론.md#6-내부-구현-핵심만) | 읽은 쿠키로 삭제하면 `Path`가 빠진 헤더가 나간다 |
| (이름, Domain, Path)가 다르면 다른 쿠키다 | 5.1-4, 함정 3 | 로그인 헤더와 로그아웃 헤더의 `Path` 비교 |
| Tomcat이 비 ASCII 값을 거부한다. MockMvc는 거부하지 않는다 | 6.2, 함정 4 | 같은 요청을 MockMvc와 실제 Tomcat(RANDOM_PORT)으로 보낸다 |
| `ResponseCookie`로 SameSite·HttpOnly·Secure를 붙인다 | 6.3 | `Set-Cookie` 문자열 단언 |
| `__Host-` 접두어 조건 (Secure, Path=/, Domain 없음) | 4장, 함정 6 | `Set-Cookie`에 Domain이 없는지 단언 |
| CORS 자격 증명 설정 | 6.5, 함정 1 | Preflight 응답의 `Access-Control-Allow-Credentials` 단언 |

## 3. 잘못된 코드 먼저

```java
package com.example.cookie.bad;

import jakarta.servlet.http.Cookie;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class BadCookieController {

    // 문제 1: 사용자 입력을 인코딩 없이 쿠키 값으로 쓴다
    @GetMapping("/bad/nickname")
    public String setNickname(@RequestParam String value, HttpServletResponse response) {
        response.addCookie(new Cookie("nickname", value));
        return "ok";
    }

    // 문제 2: 로그인은 Path=/api로 굽는다
    // 문제 3: Secure, SameSite가 없다
    @PostMapping("/api/bad/login")
    public String login(HttpServletResponse response) {
        Cookie token = new Cookie("token", "abc123");
        token.setPath("/api");
        token.setHttpOnly(true);
        response.addCookie(token);
        return "ok";
    }

    // 문제 4: 읽은 쿠키를 그대로 만료시킨다
    @PostMapping("/auth/bad/logout")
    public String logout(HttpServletRequest request, HttpServletResponse response) {
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if ("token".equals(cookie.getName())) {
                    cookie.setMaxAge(0);
                    response.addCookie(cookie);
                }
            }
        }
        return "ok";
    }
}
```

| 문제 | 실제로 생기는 일 | 이론 문서 |
|---|---|---|
| 1. 인코딩 없는 값 | `?value=홍길동`이면 실제 Tomcat에서 `IllegalArgumentException` → 500. MockMvc 테스트는 통과한다 | 함정 4 |
| 2·4. Path 불일치 | 로그인 응답은 `Path=/api`, 로그아웃 응답은 **Path가 없다**. `getCookies()`로 읽은 객체의 `getPath()`는 null이기 때문이다. 브라우저는 로그아웃 요청 경로를 보고 기본 Path를 `/auth/bad`로 잡는다. 키가 달라서 `token`은 지워지지 않는다 | 함정 3 |
| 3. 속성 누락 | Secure가 없어 HTTP로도 전송된다. SameSite가 없어 브라우저마다 동작이 달라진다 | 5.2 |

## 4. 개선된 코드 (단계적으로)

### 4.1 1단계 — 값은 인코딩해서 넣고, 꺼낼 때 디코딩한다

```java
String encoded = Base64.getUrlEncoder().withoutPadding()
        .encodeToString(value.getBytes(StandardCharsets.UTF_8));
```

**좋아진 점**: Base64URL 알파벳(`A-Z a-z 0-9 - _`)은 모두 RFC 6265의 `cookie-octet`에 속한다. 사용자가 무엇을 입력하든 `Rfc6265CookieProcessor`가 거부하지 않는다. 일반 Base64의 `+`, `/`, `=`는 허용 문자이긴 하지만 URL·프록시 로그에서 다시 이스케이프되는 일이 많아 URL-safe 변형을 쓴다.

### 4.2 2단계 — 생성과 삭제를 한 클래스에 모은다

```java
public ResponseCookie create(String token) { return base(token).maxAge(TTL).build(); }
public ResponseCookie expire()            { return base("").maxAge(0).build(); }

private ResponseCookie.ResponseCookieBuilder base(String value) {
    return ResponseCookie.from(NAME, value).path(PATH).httpOnly(true).secure(true).sameSite("Lax");
}
```

**좋아진 점**: 생성과 삭제가 같은 `base()`를 거치므로 (이름, Domain, Path)가 구조적으로 같다. 함정 3이 생길 수 없다. 요청에서 읽은 `Cookie` 객체는 재사용하지 않는다.

### 4.3 3단계 — `ResponseCookie` + `__Host-` 접두어

**좋아진 점**

- `ResponseCookie`는 `Cookie` 클래스 버전과 관계없이 `SameSite`를 붙인다.
- `ResponseCookie`는 **빌드 시점에** 이름·값 문법을 Spring이 직접 검사한다. 잘못된 값이면 MockMvc 테스트에서도 예외가 나므로, "테스트는 통과하고 운영에서 500"이라는 틈이 줄어든다.
- `__Host-` 접두어를 쓰면 누군가 나중에 `.domain("example.com")`을 붙여도 **브라우저가 저장을 거부**한다. 실수가 바로 드러난다.

> `__Host-`·`Secure` 쿠키는 HTTPS에서만 저장된다. 로컬 `http://localhost`는 Chrome·Firefox가 보안 컨텍스트로 취급해 허용한다. 다른 브라우저는 확인 필요.

### 4.4 4단계 — React 개발 서버를 위한 CORS 자격 증명 설정

```java
registry.addMapping("/api/**")
        .allowedOrigins("http://localhost:3000")   // "*" 불가: allowCredentials(true)와 함께 쓰면 Spring이 시작 시 예외를 던진다
        .allowedMethods("GET", "POST")
        .allowCredentials(true);
```

```javascript
// React 쪽. credentials가 없으면 쿠키를 보내지도, Set-Cookie를 저장하지도 않는다
await fetch("http://localhost:8080/api/login", { method: "POST", credentials: "include" });
```

**좋아진 점**: 서버와 브라우저 양쪽에서 자격 증명 요청을 허용한다. 운영에서는 리버스 프록시로 같은 오리진으로 묶으면 이 설정이 필요 없다.

### 4.5 하위 버전 대응 (Java 8 / Spring 4.x 이하 / Servlet 3.x)

`ResponseCookie`는 Spring 5.0+, `Cookie#setAttribute`는 Servlet 6.0+다. 그 이전 코드베이스에서는 `Set-Cookie` 헤더를 직접 쓴다.

```java
import java.io.UnsupportedEncodingException;
import java.net.URLEncoder;
import javax.servlet.http.HttpServletResponse;

public final class LegacyCookieWriter {

    private LegacyCookieWriter() {
    }

    // javax.servlet.http.Cookie에는 SameSite 세터가 없어서 헤더 문자열을 직접 만든다.
    // Java 7에는 java.util.Base64가 없으므로 URLEncoder를 쓴다.
    public static void writeAuthCookie(HttpServletResponse response, String token, int maxAgeSeconds)
            throws UnsupportedEncodingException {
        String value = URLEncoder.encode(token, "UTF-8");
        StringBuilder header = new StringBuilder();
        header.append("__Host-token=").append(value)
              .append("; Path=/")
              .append("; Max-Age=").append(maxAgeSeconds)
              .append("; Secure; HttpOnly; SameSite=Lax");
        // addCookie가 아니라 addHeader: 컨테이너의 쿠키 처리기를 거치지 않으므로 값 검증은 직접 책임진다
        response.addHeader("Set-Cookie", header.toString());
    }
}
```

> Spring Framework 3.x 시절(Servlet 2.5)에는 `Cookie#setHttpOnly`도 없었다(Servlet 3.0에서 추가). 위처럼 헤더를 직접 쓰는 방법이 유일하다.

### `good/AuthCookieManager.java`

```java
package com.example.cookie.good;

import java.time.Duration;
import org.springframework.http.ResponseCookie;
import org.springframework.stereotype.Component;

@Component
public class AuthCookieManager {

    // __Host- 접두어: 브라우저가 Secure + Path=/ + Domain 없음을 강제한다
    public static final String NAME = "__Host-token";

    private static final String PATH = "/";
    private static final Duration TTL = Duration.ofMinutes(30);

    public ResponseCookie create(String token) {
        return base(token).maxAge(TTL).build();
    }

    // 삭제도 생성과 같은 base()를 거친다. (이름, Domain, Path) 키가 어긋날 수 없다
    public ResponseCookie expire() {
        return base("").maxAge(0).build();
    }

    private ResponseCookie.ResponseCookieBuilder base(String value) {
        return ResponseCookie.from(NAME, value)
                .path(PATH)
                // domain()은 의도적으로 호출하지 않는다: 호스트 전용 쿠키로 둔다
                .httpOnly(true)
                .secure(true)
                // 상태 변경 API를 GET으로 만들지 않는다는 전제에서 Lax. 결제 콜백 등은 별도 쿠키로 분리한다
                .sameSite("Lax");
    }
}
```

### `good/NicknameCookieCodec.java`

```java
package com.example.cookie.good;

import java.nio.charset.StandardCharsets;
import java.util.Base64;

public final class NicknameCookieCodec {

    private NicknameCookieCodec() {
    }

    // Base64URL 알파벳은 전부 RFC 6265 cookie-octet이라 Tomcat이 거부하지 않는다
    public static String encode(String raw) {
        return Base64.getUrlEncoder().withoutPadding()
                .encodeToString(raw.getBytes(StandardCharsets.UTF_8));
    }

    public static String decode(String encoded) {
        return new String(Base64.getUrlDecoder().decode(encoded), StandardCharsets.UTF_8);
    }
}
```

### `good/GoodCookieController.java`

```java
package com.example.cookie.good;

import java.time.Duration;
import java.util.UUID;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseCookie;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.CookieValue;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api")
public class GoodCookieController {

    private final AuthCookieManager authCookieManager;

    public GoodCookieController(AuthCookieManager authCookieManager) {
        this.authCookieManager = authCookieManager;
    }

    @PostMapping("/login")
    public ResponseEntity<String> login() {
        // 학습용 가짜 토큰. 쿠키에는 추측 불가능한 식별자만 담고, 권한 같은 데이터는 담지 않는다
        String token = UUID.randomUUID().toString();
        return ResponseEntity.ok()
                .header(HttpHeaders.SET_COOKIE, authCookieManager.create(token).toString())
                .body("login");
    }

    @PostMapping("/logout")
    public ResponseEntity<String> logout() {
        return ResponseEntity.ok()
                .header(HttpHeaders.SET_COOKIE, authCookieManager.expire().toString())
                .body("logout");
    }

    @GetMapping("/me")
    public ResponseEntity<String> me(
            @CookieValue(name = AuthCookieManager.NAME, required = false) String token) {
        if (token == null || token.isEmpty()) {
            return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body("no token");
        }
        return ResponseEntity.ok("token=" + token);
    }

    @GetMapping("/nickname")
    public ResponseEntity<String> setNickname(@RequestParam String value) {
        ResponseCookie cookie = ResponseCookie.from("nickname", NicknameCookieCodec.encode(value))
                .path("/")
                .maxAge(Duration.ofDays(30))
                .sameSite("Lax")
                // UI 표시용이라 HttpOnly를 끈다. JS가 읽어야 하는 값만 이렇게 둔다
                .httpOnly(false)
                .secure(true)
                .build();
        return ResponseEntity.ok()
                .header(HttpHeaders.SET_COOKIE, cookie.toString())
                .body("ok");
    }

    @GetMapping("/nickname/read")
    public String readNickname(@CookieValue(name = "nickname", required = false) String encoded) {
        return encoded == null ? "(none)" : NicknameCookieCodec.decode(encoded);
    }
}
```

```java
package com.example.cookie.config;

import org.springframework.context.annotation.Configuration;
```

### 7.1 MockMvc — 헤더 단위 검증

```java

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;

import com.example.cookie.good.AuthCookieManager;
import jakarta.servlet.http.Cookie;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.HttpHeaders;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.MvcResult;

@SpringBootTest
@AutoConfigureMockMvc
class CookieMockMvcTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    @DisplayName("잘못된 로그아웃: 읽은 쿠키를 재사용하면 Path가 빠져 로그인 쿠키와 키가 달라진다")
    void badLogoutLosesPath() throws Exception {
        String loginHeader = mockMvc.perform(post("/api/bad/login"))
                .andReturn().getResponse().getHeader(HttpHeaders.SET_COOKIE);

        String logoutHeader = mockMvc.perform(post("/auth/bad/logout")
                        .cookie(new Cookie("token", "abc123")))
                .andReturn().getResponse().getHeader(HttpHeaders.SET_COOKIE);

        assertThat(loginHeader).contains("Path=/api");
        // 서버로는 이름=값만 오므로 getPath()가 null → Path 속성 없이 나간다
        assertThat(logoutHeader).doesNotContain("Path=");
        assertThat(logoutHeader).doesNotContain("HttpOnly");
    }

    @Test
    @DisplayName("함정 재현: MockMvc는 한글 쿠키 값을 막지 않는다 (실제 Tomcat 테스트와 비교)")
    void mockMvcDoesNotValidateCookieValue() throws Exception {
        MvcResult result = mockMvc.perform(get("/bad/nickname").param("value", "홍길동"))
                .andExpect(status().isOk())
                .andReturn();

        assertThat(result.getResponse().getCookie("nickname").getValue()).isEqualTo("홍길동");
    }

    @Test
    @DisplayName("생성과 삭제 쿠키는 이름·Path가 같고 Domain이 없다")
    void createAndExpireShareSameKey() throws Exception {
        String created = mockMvc.perform(post("/api/login"))
                .andReturn().getResponse().getHeader(HttpHeaders.SET_COOKIE);
        String expired = mockMvc.perform(post("/api/logout"))
                .andReturn().getResponse().getHeader(HttpHeaders.SET_COOKIE);

        assertThat(created).startsWith(AuthCookieManager.NAME + "=")
                .contains("Path=/", "Secure", "HttpOnly", "SameSite=Lax", "Max-Age=1800")
                .doesNotContain("Domain=");
        assertThat(expired).startsWith(AuthCookieManager.NAME + "=;")
                .contains("Path=/", "Max-Age=0", "Secure", "HttpOnly", "SameSite=Lax")
                .doesNotContain("Domain=");
    }

    @Test
    @DisplayName("토큰 쿠키가 있으면 200, 없으면 401")
    void readsCookieValue() throws Exception {
        mockMvc.perform(get("/api/me"))
                .andExpect(status().isUnauthorized());

        mockMvc.perform(get("/api/me").cookie(new Cookie(AuthCookieManager.NAME, "t-1")))
                .andExpect(status().isOk());
    }

    @Test
    @DisplayName("CORS preflight: 특정 오리진 + 자격 증명 허용")
    void corsPreflightAllowsCredentials() throws Exception {
        mockMvc.perform(options("/api/me")
                        .header(HttpHeaders.ORIGIN, "http://localhost:3000")
                        .header(HttpHeaders.ACCESS_CONTROL_REQUEST_METHOD, "GET"))
                .andExpect(status().isOk())
                .andExpect(header().string(HttpHeaders.ACCESS_CONTROL_ALLOW_ORIGIN, "http://localhost:3000"))

    @Test
    @DisplayName("허용하지 않은 오리진의 preflight는 403")
    void corsRejectsUnknownOrigin() throws Exception {
        mockMvc.perform(options("/api/me")
                        .header(HttpHeaders.ORIGIN, "https://evil.example")
                        .header(HttpHeaders.ACCESS_CONTROL_REQUEST_METHOD, "GET"))
                .andExpect(status().isForbidden());
    }
```

### 7.2 실제 Tomcat — 쿠키 처리기 검증

```java
package com.example.cookie;

import static org.assertj.core.api.Assertions.assertThat;

import java.net.URI;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.web.client.TestRestTemplate;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.util.UriComponentsBuilder;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class CookieRealTomcatTest {

    @Autowired
    TestRestTemplate rest;

    private URI nicknameUri(String path, String value) {
        // 한글 쿼리 파라미터를 한 번만 인코딩하기 위해 URI를 직접 만든다
        return UriComponentsBuilder.fromPath(path)
                .queryParam("value", value)
                .encode()
                .build()
                .toUri();
    }

    @Test
    @DisplayName("실제 Tomcat의 Rfc6265CookieProcessor는 한글 쿠키 값을 거부해 500을 낸다")
    void tomcatRejectsNonAsciiCookieValue() {
        ResponseEntity<String> response =
                rest.getForEntity(nicknameUri("/bad/nickname", "홍길동"), String.class);

        assertThat(response.getStatusCode()).isEqualTo(HttpStatus.INTERNAL_SERVER_ERROR);
        // 메시지 문구는 Tomcat 버전에 따라 다를 수 있어 핵심 단어만 확인한다
        assertThat(response.getBody()).contains("invalid character");
    }

    @Test
    @DisplayName("Base64URL로 인코딩하면 Tomcat을 통과하고, 읽을 때 원문으로 복원된다")
    void encodedValueRoundTrips() {
        ResponseEntity<String> set =
                rest.getForEntity(nicknameUri("/api/nickname", "홍길동"), String.class);
        assertThat(set.getStatusCode()).isEqualTo(HttpStatus.OK);

        String setCookie = set.getHeaders().getFirst(HttpHeaders.SET_COOKIE);
        String nameValue = setCookie.substring(0, setCookie.indexOf(';'));   // "nickname=7ZmN6ri464-Z"

        HttpHeaders headers = new HttpHeaders();
        headers.add(HttpHeaders.COOKIE, nameValue);
        ResponseEntity<String> read = rest.exchange(
                "/api/nickname/read",
                org.springframework.http.HttpMethod.GET,
                new org.springframework.http.HttpEntity<>(headers),
                String.class);

        assertThat(read.getBody()).isEqualTo("홍길동");
    }
}
```

## 8. 변형 실습

1. **`AuthCookieManager.base()`에 `.domain("localhost")`를 추가하면?**
   서버는 아무 에러 없이 `Domain=localhost`가 붙은 헤더를 보낸다. 브라우저 개발자 도구(Application → Cookies)를 보면 쿠키가 **저장되지 않았다**. `__Host-` 접두어는 Domain 속성이 있으면 거부되기 때문이다. 이름을 `token`으로 바꾸면 저장된다. 접두어가 실수를 잡아주는 장치라는 것을 확인한다.

2. **`sameSite("Lax")`를 `sameSite("None")`으로 바꾸고 `.secure(false)`로 바꾸면?**
   Chrome 콘솔에 "This Set-Cookie was blocked because it had the SameSite=None attribute but did not have the Secure attribute" 경고가 뜨고 쿠키가 저장되지 않는다(문구는 브라우저 버전에 따라 다름). `SameSite=None`은 `Secure`가 필수다.

3. **`WebConfig`의 `allowedOrigins("http://localhost:3000")`을 `allowedOrigins("*")`로 바꾸면?**
   애플리케이션이 첫 CORS 요청 처리 시점(또는 설정 검증 시점)에 `IllegalArgumentException: When allowCredentials is true, allowedOrigins cannot contain the special value "*"...`를 던진다. 여러 오리진을 패턴으로 허용해야 하면 `allowedOriginPatterns("http://localhost:*")`를 쓴다. 이 메서드는 실제 요청 오리진을 그대로 돌려주므로 브라우저 규칙에 맞는다.
