# 대칭키 암호화 — 예제

관련 문서: [이론](./대칭키암호화-이론.md) · [해시 예제](../해시/해시-예제.md)

## 1. 예제 개요

"흔히 보이는 AES 유틸"에서 시작해 AES-GCM 유틸, 키 ID를 포함한 컬럼 암호화, JPA Converter까지 단계적으로 만든다. 데모에서는 잘못된 사용이 실제로 어떤 결과를 내는지(ECB 패턴, CBC 변조, IV 재사용 시 평문 복원)도 실행해서 확인한다.

| 예제 | 검증하는 개념 | 이론 문서 대응 |
|---|---|---|
| `BadCrypto` | ECB 기본값, 하드코딩된 문자열 키, Cipher 공유, `new String()` 저장 | 8장 함정 1·3·4·6 |
| `SymmetricDemo` 5번 | CBC 비트 뒤집기, GCM의 변조 거부 | 5-2, 함정 5 |
| `SymmetricDemo` 7번 | GCM IV 재사용 → 키 없이 평문 복원, JDK 재사용 검사의 범위 | 5-2, 6장, 함정 2 |
| `AesGcm` | 랜덤 IV, IV 앞에 붙여 저장, AAD, 태그 검증 | 3장, 5-3 |
| `FieldEncryptor` | `키ID:Base64` 저장 형식, 키 교체 | 5-4, 9-2, 함정 3·4 |
| `EncryptedStringConverter` | JPA 컬럼 자동 암복호화 | 5-4, 9-1 |

## 3. 잘못된 코드 먼저

인터넷 예제를 복사해 오면 흔히 이런 모양이 된다. 컴파일도 되고, 단일 스레드에서 바이트로 주고받으면 암복호화도 "된다". 그래서 문제를 알아채기 어렵다.

```java
package com.study.symmetric;

import java.security.GeneralSecurityException;

import javax.crypto.Cipher;
import javax.crypto.spec.SecretKeySpec;

/** 실무 레거시에서 자주 보이는 잘못된 암호화 유틸. 따라 쓰지 말 것. */
public final class BadCrypto {

    // 문제 1: 키가 소스 코드에 박혀 있다. Git 이력에 영원히 남고, 바꾸려면 재배포해야 한다.
    // 문제 2: 문자열을 그대로 키로 쓴다. 우연히 16바이트라 동작할 뿐, 사람이 고른 문자열이라 엔트로피도 낮다.
    private static final SecretKeySpec KEY = new SecretKeySpec("my-secret-key-16".getBytes(), "AES");

    // 문제 3: 상태를 가진 Cipher를 static으로 공유한다.
    private static final Cipher CIPHER;

    static {
        try {
            // 문제 4: 모드를 적지 않았다. SunJCE에서 "AES"는 "AES/ECB/PKCS5Padding"이 된다.
            CIPHER = Cipher.getInstance("AES");
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    private BadCrypto() {
    }

    public static byte[] encryptBytes(byte[] plaintext) {
        try {
            CIPHER.init(Cipher.ENCRYPT_MODE, KEY);
            return CIPHER.doFinal(plaintext);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] decryptBytes(byte[] ciphertext) {
        try {
            CIPHER.init(Cipher.DECRYPT_MODE, KEY);
            return CIPHER.doFinal(ciphertext);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static String encrypt(String plaintext) {
        // 문제 5: 암호문(임의의 바이트)을 new String()으로 문자열로 만든다.
        // UTF-8로 해석할 수 없는 바이트는 U+FFFD(�)로 바뀌어 원래 바이트를 잃는다.
        return new String(encryptBytes(plaintext.getBytes()));
    }

    public static String decrypt(String ciphertext) {
        return new String(decryptBytes(ciphertext.getBytes()));
    }
}
```

| 문제 | 실제로 일어나는 일 (6장 실행 결과) | 이론 |
|---|---|---|
| 1. 키 하드코딩 | Git에 키가 남는다. 교체할 수단(키 ID)도 없다 | 함정 3 |
| 2. 문자열 키 | `"my-secret-key"`(13바이트)였다면 `InvalidKeyException: Invalid AES key length: 13 bytes`가 난다. 16글자로 맞춰서 "해결"한 것이 이 코드다 | 함정 3 |
| 3. Cipher 공유 | 16만 번 중 틀린 결과 26,684건, 예외 69,312건 | 함정 6 |
| 4. `"AES"` = ECB | 같은 16바이트 평문 블록 두 개가 같은 암호 블록 `89d80d4b...`로 나온다. 같은 입력은 항상 같은 암호문이다 | 함정 1 |
| 5. `new String(암호문)` | 16바이트 암호문이 문자열을 거쳐 26바이트가 되고, 복호화는 `IllegalBlockSizeException`으로 실패한다 | 함정 4 |

문제 5는 `encrypt`/`decrypt` 문자열 API를 처음 쓰는 순간 드러난다. 그래서 실무에서는 대개 Base64만 추가해서 "고친" 상태로 운영되고, **문제 1~4는 그대로 남는다.**

## 4. 개선된 코드

### 1단계: AES-GCM과 랜덤 IV — `AesGcm`

- 변환 문자열을 `"AES/GCM/NoPadding"`으로 전부 적는다 → **문제 4 해결**. 패턴이 사라지고 변조도 감지한다
- `Cipher`는 호출마다 새로 만들고, `SecureRandom`만 공유한다 → **문제 3 해결**
- 키는 `KeyGenerator.init(256)`으로 만든 난수다. 외부에서는 Base64로 받아 길이를 검증한다 → **문제 2 해결**
- 출력은 `[IV 12][암호문][태그 16]` 하나의 `byte[]`. IV를 따로 관리할 필요가 없다

핵심 부분(전체는 5장):

```java
byte[] iv = new byte[IV_LENGTH];
RANDOM.nextBytes(iv);
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(TAG_LENGTH_BITS, iv));
if (aad != null) {
    cipher.updateAAD(aad);
}
byte[] ciphertextAndTag = cipher.doFinal(plaintext);
return ByteBuffer.allocate(IV_LENGTH + ciphertextAndTag.length).put(iv).put(ciphertextAndTag).array();
```

복호화 실패는 `CryptoException` 하나로 감싼다. 키가 틀렸는지, 변조됐는지, AAD가 다른지를 밖에서 구분할 수 없게 하기 위해서다([이론 6장](./대칭키암호화-이론.md#6-내부-구현-핵심만)의 `AEADBadTagException` 설명).

**좋아진 점**: 같은 평문도 매번 다른 암호문이 되고, 1비트만 바뀌어도 복호화가 거부된다.
**남은 문제**: 결과가 `byte[]`라서 문자열 컬럼에 넣기 어렵고, 키를 바꾸면 기존 데이터를 읽을 방법이 없다.

### 2단계: 저장 형식에 키 ID — `FieldEncryptor`

- 저장 형식 `"k1:" + Base64(...)` → **문제 5 해결**(문자열 안전), **문제 1의 교체 불가 해결**
- 키 목록 `Map<키ID, SecretKey>`와 활성 키 ID를 받는다. 암호화는 항상 활성 키로, 복호화는 접두어의 키로 한다
- `needsReEncryption()`으로 예전 키 데이터를 찾아 배치로 재암호화할 수 있다([이론 9-2](./대칭키암호화-이론.md#9-2-키-교체-key-rotation))
- `context` 인자는 AAD로 들어간다. "전화번호 컬럼용으로 암호화한 값"을 "계좌번호 컬럼"에 옮겨 넣으면 복호화가 실패한다

**좋아진 점**: 키를 무중단으로 교체할 수 있다. [해시의 `DelegatingPasswordEncoder`](../해시/해시-이론.md#6-내부-구현-핵심만)가 `{bcrypt}` 접두어로 알고리즘을 교체하는 것과 같은 구조다.

### 3단계: JPA에 연결 — `EncryptedStringConverter`

```java
@Convert(converter = EncryptedStringConverter.class)
@Column(name = "phone_enc", length = 255)
private String phone;
```

- 서비스 코드는 평문만 다루고, 저장·조회 시 Hibernate가 Converter를 호출한다([이론 5-4](./대칭키암호화-이론.md#5-4-spring--jpa-계층에서의-흐름-컬럼-암호화))
- `null`은 `null`로 유지한다. `null`을 암호화하면 "값 없음"과 "빈 문자열"을 구분할 수 없게 되고 `IS NULL` 조회도 깨진다
- Converter는 행을 모르므로 AAD에는 용도 문자열만 넣는다. 행 단위로 묶어야 하는 값(9-3의 OAuth 토큰 등)은 서비스 계층에서 `FieldEncryptor`를 직접 호출하고 `"oauth:" + userId`를 AAD로 준다

**남은 한계**: 이 컬럼으로는 검색할 수 없다. `findByPhone()`은 항상 빈 결과다([이론 함정 7](./대칭키암호화-이론.md#함정-7-암호화한-컬럼으로-검색한다)). 검색이 필요하면 HMAC 블라인드 인덱스 컬럼을 추가한다.

### AesGcm.java

```java
package com.study.symmetric;

import java.nio.ByteBuffer;
import java.security.GeneralSecurityException;
import java.security.NoSuchAlgorithmException;
import java.security.SecureRandom;
import java.util.Base64;

import javax.crypto.AEADBadTagException;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;

/**
 * AES-256-GCM 암복호화.
 * 출력 형식: [IV 12바이트][암호문][인증 태그 16바이트]
 */
public final class AesGcm {

    // GCM은 12바이트(96비트) IV일 때 가장 효율적이고 표준(NIST SP 800-38D)이 권장하는 길이다.
    private static final int IV_LENGTH = 12;
    private static final int TAG_LENGTH_BITS = 128;
    // SecureRandom은 스레드 안전하므로 공유한다. Cipher와 다르다.
    private static final SecureRandom RANDOM = new SecureRandom();

    private final SecretKey key;

    public AesGcm(SecretKey key) {
        if (!"AES".equals(key.getAlgorithm())) {
            throw new IllegalArgumentException("AES 키가 아니다: " + key.getAlgorithm());
        }
        this.key = key;
    }

    public static SecretKey generateKey() {
        try {
            KeyGenerator generator = KeyGenerator.getInstance("AES");
            // 키는 사람이 고른 문자열이 아니라 SecureRandom으로 만든 256비트 난수여야 한다.
            generator.init(256);
            return generator.generateKey();
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);
        }
    }

    public static SecretKey keyFromBase64(String base64Key) {
        byte[] raw = Base64.getDecoder().decode(base64Key);
        if (raw.length != 16 && raw.length != 24 && raw.length != 32) {
            throw new IllegalArgumentException("AES 키는 16/24/32바이트여야 한다: " + raw.length + "바이트");
        }
        return new SecretKeySpec(raw, "AES");
    }

    public byte[] encrypt(byte[] plaintext, byte[] aad) {
        // 같은 키로 같은 IV를 두 번 쓰면 GCM은 기밀성과 무결성이 모두 무너진다. 매번 새로 뽑는다.
        byte[] iv = new byte[IV_LENGTH];
        RANDOM.nextBytes(iv);
        try {
            // Cipher는 init~doFinal 사이의 상태를 가진다. 호출마다 새로 만든다.
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(TAG_LENGTH_BITS, iv));
            if (aad != null) {
                // AAD는 암호화되지 않지만 태그 계산에 들어간다. 복호화할 때 같은 값을 줘야만 성공한다.
                cipher.updateAAD(aad);
            }
            byte[] ciphertextAndTag = cipher.doFinal(plaintext);
            // IV는 비밀이 아니다. 복호화할 때 필요하므로 암호문 앞에 붙여 함께 저장한다.
            return ByteBuffer.allocate(IV_LENGTH + ciphertextAndTag.length)
                    .put(iv)
                    .put(ciphertextAndTag)
                    .array();
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public byte[] decrypt(byte[] ivAndCiphertext, byte[] aad) {
        if (ivAndCiphertext.length < IV_LENGTH + TAG_LENGTH_BITS / 8) {
            throw new CryptoException("복호화 실패");
        }
        try {
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(TAG_LENGTH_BITS, ivAndCiphertext, 0, IV_LENGTH));
            if (aad != null) {
                cipher.updateAAD(aad);
            }
            // GCM은 태그를 확인하기 전에는 평문을 하나도 돌려주지 않는다. 변조된 평문이 새어 나가지 않는다.
            return cipher.doFinal(ivAndCiphertext, IV_LENGTH, ivAndCiphertext.length - IV_LENGTH);
        } catch (AEADBadTagException e) {
            throw new CryptoException("복호화 실패", e);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }
}
```

### FieldEncryptor.java

```java
package com.study.symmetric;

import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.HashMap;
import java.util.Map;

import javax.crypto.SecretKey;

/**
 * DB 컬럼 암호화용. 저장 형식: "{키ID}:{Base64(IV + 암호문 + 태그)}"
 * 키 ID를 함께 저장해야 키를 교체(rotation)한 뒤에도 예전 데이터를 복호화할 수 있다.
 */
public final class FieldEncryptor {

    private final String activeKeyId;
    private final Map<String, AesGcm> ciphers = new HashMap<>();

    public FieldEncryptor(String activeKeyId, Map<String, SecretKey> keys) {
        if (!keys.containsKey(activeKeyId)) {
            throw new IllegalArgumentException("활성 키가 키 목록에 없다: " + activeKeyId);
        }
        for (Map.Entry<String, SecretKey> e : keys.entrySet()) {
            if (e.getKey().contains(":")) {
                throw new IllegalArgumentException("키 ID에 ':'를 쓸 수 없다: " + e.getKey());
            }
            ciphers.put(e.getKey(), new AesGcm(e.getValue()));
        }
        this.activeKeyId = activeKeyId;
    }

    public String encrypt(String plaintext, String context) {
        if (plaintext == null) {
            return null;
        }
        byte[] encrypted = ciphers.get(activeKeyId).encrypt(
                plaintext.getBytes(StandardCharsets.UTF_8), aad(context));
        // 암호문은 임의의 바이트라서 new String()으로 바꾸면 깨진다. 문자열 컬럼에는 Base64로 넣는다.
        return activeKeyId + ":" + Base64.getEncoder().encodeToString(encrypted);
    }

    public String decrypt(String stored, String context) {
        if (stored == null) {
            return null;
        }
        int sep = stored.indexOf(':');
        if (sep < 0) {
            throw new CryptoException("복호화 실패");
        }
        AesGcm cipher = ciphers.get(stored.substring(0, sep));
        if (cipher == null) {
            throw new CryptoException("복호화 실패");
        }
        byte[] raw;
        try {
            raw = Base64.getDecoder().decode(stored.substring(sep + 1));
        } catch (IllegalArgumentException e) {
            throw new CryptoException("복호화 실패", e);
        }
        return new String(cipher.decrypt(raw, aad(context)), StandardCharsets.UTF_8);
    }

    /** 예전 키로 암호화된 값이면 true. 배치나 조회 시점에 새 키로 다시 암호화하는 데 쓴다. */
    public boolean needsReEncryption(String stored) {
        return stored != null && !stored.startsWith(activeKeyId + ":");
    }

    private static byte[] aad(String context) {
        return context == null ? null : context.getBytes(StandardCharsets.UTF_8);
    }
}
```

```java
package com.study.symmetric;

import jakarta.persistence.AttributeConverter;
import jakarta.persistence.Converter;

/**
 * JPA 엔티티 필드를 저장할 때 암호화하고, 읽을 때 복호화한다.
 * 엔티티에서 @Convert(converter = EncryptedStringConverter.class)로 붙인다.

 * Spring Boot는 Hibernate에 SpringBeanContainer를 연결해 주므로 생성자 주입이 동작한다.

public class EncryptedStringConverter implements AttributeConverter<String, String> {

    // AttributeConverter는 어느 행(row)인지 모른다. 그래서 AAD에 행 ID를 넣을 수 없고, 용도 문자열만 넣는다.
    // 이 값 때문에 "다른 용도로 암호화된 값"을 이 컬럼에 옮겨 넣으면 복호화가 실패한다.
    private static final String CONTEXT = "pii:v1";

    private final FieldEncryptor encryptor;

    public EncryptedStringConverter(FieldEncryptor encryptor) {
        this.encryptor = encryptor;
    }

    @Override
    public String convertToDatabaseColumn(String attribute) {
        return encryptor.encrypt(attribute, CONTEXT);
    }

    @Override
    public String convertToEntityAttribute(String dbData) {
        return encryptor.decrypt(dbData, CONTEXT);
    }
```

```java
    private static void cbcBitFlipping() throws GeneralSecurityException {
        System.out.println("== 5. CBC는 변조를 모른다 (비트 뒤집기) ==");
        SecretKey key = AesGcm.generateKey();
        byte[] iv = new byte[16];
        new SecureRandom().nextBytes(iv);
        Cipher enc = Cipher.getInstance("AES/CBC/PKCS5Padding");
        enc.init(Cipher.ENCRYPT_MODE, key, new IvParameterSpec(iv));
        byte[] ct = enc.doFinal("amount=1000;to=A".getBytes(StandardCharsets.UTF_8));

        // 공격자는 키를 모른다. 평문의 형식만 안다. IV의 7번째 바이트를 ('1' XOR '9')로 뒤집는다.
        byte[] tamperedIv = iv.clone();
        tamperedIv[7] ^= (byte) ('1' ^ '9');
        Cipher dec = Cipher.getInstance("AES/CBC/PKCS5Padding");
        dec.init(Cipher.DECRYPT_MODE, key, new IvParameterSpec(tamperedIv));
        System.out.println("원래 평문 : amount=1000;to=A");
        System.out.println("CBC 복호화: " + new String(dec.doFinal(ct), StandardCharsets.UTF_8) + "  ← 예외 없이 금액이 바뀜");

        AesGcm gcm = new AesGcm(key);
        byte[] gcmCt = gcm.encrypt("amount=1000;to=A".getBytes(StandardCharsets.UTF_8), null);
        gcmCt[12 + 7] ^= (byte) ('1' ^ '9'); // GCM은 CTR 기반이라 암호문 바이트를 뒤집으면 평문 같은 위치가 뒤집힌다
        try {
            gcm.decrypt(gcmCt, null);
        } catch (CryptoException e) {
            System.out.println("GCM 복호화: CryptoException (원인: " + e.getCause().getClass().getSimpleName()
                    + ": " + e.getCause().getMessage() + ")");
        }

    private static void gcmNonceReuse() throws GeneralSecurityException {
        System.out.println("== 7. GCM에서 IV를 재사용하면 ==");
        SecretKey key = AesGcm.generateKey();
        byte[] fixedIv = new byte[12]; // 0으로 고정한 IV
        Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
        c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, fixedIv));
        c.doFinal("first".getBytes(StandardCharsets.UTF_8));
        try {
            c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, fixedIv));
        } catch (GeneralSecurityException | IllegalStateException e) {
            System.out.println("같은 Cipher 객체로 재사용 → " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }

        // 새 Cipher 객체를 만들면 JDK는 막지 못한다. 서버 재시작, 여러 인스턴스, 고정 IV 상수가 이런 경우다.
        byte[] p1 = "salary=03000000".getBytes(StandardCharsets.UTF_8);
        byte[] p2 = "salary=09500000".getBytes(StandardCharsets.UTF_8);
        byte[] c1 = encryptWithIv(key, fixedIv, p1);
        byte[] c2 = encryptWithIv(key, fixedIv, p2);
        // 공격자는 키를 모른다. c1, c2와 "p1이 무엇인지"(예: 자기 연봉)만 안다.
        byte[] recovered = new byte[p1.length];
        for (int i = 0; i < p1.length; i++) {
            recovered[i] = (byte) (c1[i] ^ c2[i] ^ p1[i]);
        }
        System.out.println("공격자가 아는 p1 : " + new String(p1, StandardCharsets.UTF_8));
        System.out.println("c1 XOR c2 XOR p1 : " + new String(recovered, StandardCharsets.UTF_8) + "  ← 키 없이 남의 평문 복원");
        System.out.println();
    }

    private static byte[] encryptWithIv(SecretKey key, byte[] iv, byte[] plain) throws GeneralSecurityException {
        Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
        c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));
        return c.doFinal(plain);
    }

    private static void sharedCipherRace() throws Exception {
        System.out.println("== 8. static Cipher 공유 시 경쟁 상태 ==");
        ExecutorService pool = Executors.newFixedThreadPool(8);
        try {
            List<Future<int[]>> futures = new ArrayList<>();
            for (int t = 0; t < 8; t++) {
                final int threadNo = t;
                futures.add(pool.submit(() -> {
                    int wrong = 0;
                    int exceptions = 0;
                    for (int i = 0; i < 20_000; i++) {
                        byte[] plain = ("t" + threadNo + "-" + i).getBytes(StandardCharsets.UTF_8);

                            if (!Arrays.equals(plain, back)) {
                                wrong++;
                            }
                        } catch (RuntimeException e) {
                            exceptions++;
                        }
                    }
                    return new int[] {wrong, exceptions};
                }));
            }
            int wrong = 0;
            int exceptions = 0;
            for (Future<int[]> f : futures) {
                int[] r = f.get();
                wrong += r[0];
                exceptions += r[1];
            }
            System.out.println("160,000번 암호화→복호화 중 틀린 결과: " + wrong + "건, 예외: " + exceptions + "건");
        } finally {
            pool.shutdown();
        }
        System.out.println();
    }

    private static void keyRotation() {
        System.out.println("== 9. 키 교체 (key rotation) ==");
        SecretKey k1 = AesGcm.generateKey();

        String reEncrypted = after.encrypt(after.decrypt(stored, "member.phone"), "member.phone");
        System.out.println("재암호화 저장값: " + reEncrypted);
        System.out.println("다시 암호화가 필요한가? " + after.needsReEncryption(reEncrypted));
        System.out.println();
    }

    private static void jpaConverter() {

    }
```

### (참고) Spring Boot 빈 설정 — Java Config + properties

데모에서는 실행하지 않은 코드다. 위 클래스들을 Spring Boot에 연결하는 방법을 보여 준다.

```yaml
# application.yml — 키 값은 파일에 쓰지 않고 환경 변수(또는 Vault·KMS)에서 주입한다
app:
  crypto:
    active-key-id: k2
    keys:
      k1: ${CRYPTO_KEY_K1}   # 교체 전 키. 재암호화 배치가 끝나면 제거
      k2: ${CRYPTO_KEY_K2}
```

```java
package com.study.symmetric;

import java.util.HashMap;
import java.util.Map;

import javax.crypto.SecretKey;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableConfigurationProperties(CryptoConfig.CryptoProperties.class)
public class CryptoConfig {

    @Bean
    public FieldEncryptor fieldEncryptor(CryptoProperties props) {
        Map<String, SecretKey> keys = new HashMap<>();
        props.keys().forEach((id, base64) -> keys.put(id, AesGcm.keyFromBase64(base64)));
        // 키가 잘못됐으면 첫 요청이 아니라 애플리케이션 시작 시점에 실패하도록 빈 생성 단계에서 검증한다.
        return new FieldEncryptor(props.activeKeyId(), keys);
    }

    // Java 16+ record. Java 8~15라면 getter/setter가 있는 일반 클래스로 바꾼다.
    @ConfigurationProperties(prefix = "app.crypto")
    public record CryptoProperties(String activeKeyId, Map<String, String> keys) {
    }
}
```

결과 읽기:

- **2번**: 블록1과 블록2가 같다. `"AES"`와 `"AES/ECB/PKCS5Padding"`의 결과가 바이트 단위로 같으므로 기본 모드가 ECB임이 확인된다. 블록3은 평문이 16의 배수라 붙은 패딩 블록(16바이트 전부 `0x10`)이다.
- **3번**: 암호문 16바이트 중 UTF-8로 해석할 수 없는 바이트가 3바이트짜리 U+FFFD로 바뀌어 26바이트가 됐다. 원래 바이트는 복구할 수 없다.
- **5번**: 공격자는 키를 모르고 "7번째 글자가 금액의 첫 자리"라는 형식만 안다. CBC는 그것만으로 금액을 바꿀 수 있었다. 같은 조작을 GCM에 하면 `Tag mismatch`로 거부된다.
- **7번**: JDK는 같은 Cipher 객체에서의 재사용만 막는다. 새 객체 두 개로 같은 IV를 쓰자 키 없이 상대 평문이 복원됐다. **JDK의 검사를 믿지 말고 IV를 매번 랜덤으로 만들어야 하는 이유다.**
- **8번**: 160,000번 중 약 60%가 실패했다. 예외 종류를 따로 세 보면 `BadPaddingException`(메시지가 "bad key"를 암시한다), `IllegalBlockSizeException`, `IllegalStateException: Cipher not initialized`, `ArrayIndexOutOfBoundsException` 순이었다. 키 문제로 오진하기 쉽다.
- **9번**: 활성 키를 `k2`로 바꾼 뒤에도 `k1:` 값을 읽고, 다시 암호화하면 `k2:`가 된다.
- **10번**: 13자 전화번호가 59자로 저장된다(`k1:` 3자 + Base64(12 + 13 + 16 = 41바이트) 56자). 컬럼 길이를 정할 때 이 계산을 쓴다.
- **11번**: Cipher를 매번 새로 만들어도 1KB 기준 초당 약 600MB를 처리한다. "성능 때문에 Cipher를 공유한다"는 근거가 약하다.

```java
package com.study.symmetric;

import static org.junit.jupiter.api.Assertions.assertArrayEquals;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertNull;
import static org.junit.jupiter.api.Assertions.assertThrows;
import static org.junit.jupiter.api.Assertions.assertTrue;

import java.nio.charset.StandardCharsets;
import java.security.InvalidAlgorithmParameterException;
import java.security.InvalidKeyException;
import java.util.Arrays;
import java.util.Map;

import javax.crypto.Cipher;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;

import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Nested;
import org.junit.jupiter.api.Test;

class SymmetricTest {

    private static byte[] utf8(String s) {
        return s.getBytes(StandardCharsets.UTF_8);
    }

    @Nested
    @DisplayName("AES-GCM 기본 성질")
    class Gcm {

        private final AesGcm aes = new AesGcm(AesGcm.generateKey());

        @Test
        @DisplayName("같은 키로 복호화하면 원문이 나온다")
        void roundTrip() {
            assertArrayEquals(utf8("010-1234-5678"), aes.decrypt(aes.encrypt(utf8("010-1234-5678"), null), null));
        }

        @Test
        @DisplayName("IV가 매번 랜덤이라 같은 평문도 암호문이 다르다")
        void randomIv() {
            assertFalse(Arrays.equals(aes.encrypt(utf8("same"), null), aes.encrypt(utf8("same"), null)));
        }

        @Test
        @DisplayName("저장 길이 = IV 12 + 평문 길이 + 태그 16")
        void outputLength() {
            assertEquals(12 + 13 + 16, aes.encrypt(utf8("010-1234-5678"), null).length);
        }

        @Test
        @DisplayName("암호문 1비트만 바뀌어도 복호화가 실패한다")
        void tamperDetected() {
            byte[] ct = aes.encrypt(utf8("amount=1000"), null);
            ct[ct.length - 1] ^= 1;
            assertThrows(CryptoException.class, () -> aes.decrypt(ct, null));
        }

        @Test
        @DisplayName("AAD가 다르면 복호화가 실패한다 (다른 행으로 복사한 암호문)")
        void aadBinding() {
            byte[] ct = aes.encrypt(utf8("010-1234-5678"), utf8("member:1"));
            assertArrayEquals(utf8("010-1234-5678"), aes.decrypt(ct, utf8("member:1")));
            assertThrows(CryptoException.class, () -> aes.decrypt(ct, utf8("member:2")));
        }

        @Test
        @DisplayName("다른 키로는 복호화할 수 없다")
        void wrongKey() {
            byte[] ct = aes.encrypt(utf8("secret"), null);
            assertThrows(CryptoException.class, () -> new AesGcm(AesGcm.generateKey()).decrypt(ct, null));
        }
    }

    @Nested
    @DisplayName("잘못된 사용")
    class Misuse {

        @Test
        @DisplayName("\"AES\"만 쓰면 ECB라서 같은 평문 블록이 같은 암호문 블록이 된다")
        void ecbLeaksPattern() {
            byte[] ct = BadCrypto.encryptBytes(utf8("ACCOUNT=12345678ACCOUNT=12345678"));
            assertArrayEquals(Arrays.copyOfRange(ct, 0, 16), Arrays.copyOfRange(ct, 16, 32));
        }

        @Test
        @DisplayName("문자열을 그대로 키로 쓰면 길이가 맞지 않아 init에서 실패한다")
        void stringKey() throws Exception {
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            SecretKeySpec key = new SecretKeySpec("my-secret-key".getBytes(StandardCharsets.UTF_8), "AES");
            assertThrows(InvalidKeyException.class,
                    () -> cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, new byte[12])));
        }

        @Test
        @DisplayName("암호문을 new String()으로 바꾸면 바이트가 손실된다")
        void stringCorruption() {
            byte[] raw = BadCrypto.encryptBytes(utf8("010-1234-5678"));
            byte[] roundTripped = new String(raw, StandardCharsets.UTF_8).getBytes(StandardCharsets.UTF_8);
            assertFalse(Arrays.equals(raw, roundTripped));
        }

        @Test
        @DisplayName("CBC는 IV를 조작해도 예외 없이 다른 평문을 돌려준다")
        void cbcBitFlip() throws Exception {
            SecretKey key = AesGcm.generateKey();
            byte[] iv = new byte[16];
            Cipher enc = Cipher.getInstance("AES/CBC/PKCS5Padding");
            enc.init(Cipher.ENCRYPT_MODE, key, new IvParameterSpec(iv));
            byte[] ct = enc.doFinal(utf8("amount=1000;to=A"));

            byte[] tamperedIv = iv.clone();
            tamperedIv[7] ^= (byte) ('1' ^ '9');
            Cipher dec = Cipher.getInstance("AES/CBC/PKCS5Padding");
            dec.init(Cipher.DECRYPT_MODE, key, new IvParameterSpec(tamperedIv));
            assertEquals("amount=9000;to=A", new String(dec.doFinal(ct), StandardCharsets.UTF_8));
        }

        @Test
        @DisplayName("같은 Cipher 객체로 같은 키·IV를 다시 쓰면 JDK가 막는다")
        void sameCipherIvReuseBlocked() throws Exception {
            SecretKey key = AesGcm.generateKey();
            Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
            c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, new byte[12]));
            c.doFinal(utf8("first"));
            assertThrows(InvalidAlgorithmParameterException.class,
                    () -> c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, new byte[12])));
        }

        @Test
        @DisplayName("새 Cipher로 IV를 재사용하면 키 없이 평문이 복원된다")
        void nonceReuseLeaksPlaintext() throws Exception {
            SecretKey key = AesGcm.generateKey();
            byte[] iv = new byte[12];
            byte[] p1 = utf8("salary=03000000");
            byte[] p2 = utf8("salary=09500000");
            byte[] c1 = encrypt(key, iv, p1);
            byte[] c2 = encrypt(key, iv, p2);
            byte[] recovered = new byte[p1.length];
            for (int i = 0; i < p1.length; i++) {
                recovered[i] = (byte) (c1[i] ^ c2[i] ^ p1[i]);
            }
            assertArrayEquals(p2, recovered);
        }

        private byte[] encrypt(SecretKey key, byte[] iv, byte[] plain) throws Exception {
            Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
            c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));
            return c.doFinal(plain);
        }
    }

    @Nested
    @DisplayName("컬럼 암호화와 키 교체")
    class Field {

        private final SecretKey k1 = AesGcm.generateKey();
        private final SecretKey k2 = AesGcm.generateKey();

        @Test
        @DisplayName("키를 교체해도 예전 키 ID로 저장된 값을 읽을 수 있다")
        void rotation() {
            String old = new FieldEncryptor("k1", Map.of("k1", k1)).encrypt("010-1234-5678", "ctx");
            FieldEncryptor rotated = new FieldEncryptor("k2", Map.of("k1", k1, "k2", k2));

            assertEquals("010-1234-5678", rotated.decrypt(old, "ctx"));
            assertTrue(rotated.needsReEncryption(old));
            assertTrue(rotated.encrypt("010-1234-5678", "ctx").startsWith("k2:"));
        }

        @Test
        @DisplayName("예전 키를 목록에서 빼면 그 키로 암호화된 데이터는 읽을 수 없다")
        void removedKey() {
            String old = new FieldEncryptor("k1", Map.of("k1", k1)).encrypt("010-1234-5678", "ctx");
            FieldEncryptor onlyNew = new FieldEncryptor("k2", Map.of("k2", k2));
            assertThrows(CryptoException.class, () -> onlyNew.decrypt(old, "ctx"));
        }

        @Test
        @DisplayName("Converter는 null을 null로 유지하고, 저장값은 키ID:Base64 형식이다")
        void converter() {
            EncryptedStringConverter converter =
                    new EncryptedStringConverter(new FieldEncryptor("k1", Map.of("k1", k1)));
            String column = converter.convertToDatabaseColumn("010-1234-5678");

            assertTrue(column.matches("k1:[A-Za-z0-9+/]+=*"));
            assertEquals("010-1234-5678", converter.convertToEntityAttribute(column));
            assertNull(converter.convertToDatabaseColumn(null));
            assertNull(converter.convertToEntityAttribute(null));
        }

        @Test
        @DisplayName("Base64 키 길이가 16/24/32바이트가 아니면 거부한다")
        void keyLengthValidation() {
            assertThrows(IllegalArgumentException.class, () -> AesGcm.keyFromBase64("bXktc2VjcmV0LWtleQ==")); // 13바이트
        }
    }
}
```

## 8. 변형 실습

1. **`AesGcm.encrypt`의 `RANDOM.nextBytes(iv)` 줄을 지우면(IV가 항상 0)?**
   `SymmetricTest`에서 `randomIv`만 실패하고 나머지 15개는 모두 통과한다. 하지만 7번 데모처럼 평문을 아는 공격자에게 다른 모든 평문이 노출된다. "테스트가 대부분 통과하는 치명적 버그"다. IV 랜덤성을 검증하는 테스트(`randomIv`)가 왜 반드시 있어야 하는지 생각해 보자.

2. **`FieldEncryptor`의 `context`(AAD)를 회원 ID로 바꿔 서비스 계층에서 호출하면?**
   `encrypt(phone, "member:" + id)`로 저장한 값을 SQL로 다른 회원 행에 복사(`UPDATE member SET phone_enc = (SELECT phone_enc FROM member WHERE id = 1) WHERE id = 2`)한 상황을 테스트로 만들어 보자. 복호화가 실패해야 한다. 반대로 `EncryptedStringConverter`처럼 고정 문자열이면 복사가 통과한다. 신규 회원은 INSERT 전에 ID가 없다는 문제(IDENTITY 전략)도 함께 고민해 보자. UUID를 애플리케이션에서 미리 만드는 방식이 대안이다.

3. **`"AES/GCM/NoPadding"`을 `"ChaCha20-Poly1305"`로 바꾸면?**
   Java 11+에서 동작한다. 키는 32바이트만 허용되고, 파라미터는 `GCMParameterSpec` 대신 `IvParameterSpec`(12바이트 논스)을 쓴다. 11번 속도 측정을 두 알고리즘으로 비교해 보자. AES-NI가 있는 x86 서버에서는 대개 AES-GCM이 빠르다(환경마다 다르므로 직접 측정해서 확인한다).
