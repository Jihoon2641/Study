# 비대칭키 암호화 — 예제

## 1. 예제 개요

JDK 표준 API(JCA)만으로 RSA-OAEP 암호화, 하이브리드 암호화, 전자서명(RSA·ECDSA·Ed25519), PEM 키 입출력, RS256 JWT 서명·검증을 만든다. 잘못된 RSA 사용과 "헤더를 믿는 JWT 검증기"가 실제로 어떻게 뚫리는지도 실행해서 확인한다.

| 예제 | 검증하는 개념 | 이론 문서 대응 |
|---|---|---|
| `BadRsa` | `"RSA"` = PKCS#1 v1.5, 1024비트 키, 큰 데이터 직접 암호화 | 함정 1·2 |
| `RsaOaep` | OAEP 파라미터 명시, 크기 제한 계산 | 5-2, 6장, 함정 3 |
| `HybridEncryptor` | RSA로 AES 키 감싸기(wrap), AAD로 감싼 키 바인딩 | 5-4 |
| `Signer` | RSA·ECDSA·Ed25519 서명/검증, DER vs P1363 | 5-1, 5-3, 함정 6 |
| `PemKeys` | PKCS#8·X.509 PEM 저장/로드, PKCS#1 거부 | 6장, 함정 5 |
| `MiniJwt` / `BadJwtVerifier` | RS256 JWT 구조, 알고리즘 고정 vs 헤더 신뢰 | 5-5, 함정 4 |

- Java 17 이상 권장(`String.lines`, 스위치 등). 핵심 클래스는 Java 11에서도 컴파일되지만 Ed25519는 Java 15+, `SHA256withECDSAinP1363Format`은 Java 9+가 필요하다.

## 3. 잘못된 코드 먼저

### 3-1. 흔히 보이는 RSA 유틸

```java
package com.study.asymmetric;

import java.security.GeneralSecurityException;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.PrivateKey;
import java.security.PublicKey;

import javax.crypto.Cipher;

/** 실무 레거시에서 자주 보이는 잘못된 RSA 유틸. 따라 쓰지 말 것. */
public final class BadRsa {

    private BadRsa() {
    }

    public static KeyPair generate() {
        try {
            KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA");
            // 문제 1: 1024비트. 2010년대 초부터 폐기 권고된 길이다(NIST는 2048 이상 요구).
            generator.initialize(1024);
            return generator.generateKeyPair();
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] encrypt(PublicKey publicKey, byte[] data) {
        try {
            // 문제 2: 패딩을 적지 않았다. SunJCE에서 "RSA"는 "RSA/ECB/PKCS1Padding"(PKCS#1 v1.5)이 된다.
            //         v1.5 암호화 패딩은 패딩 오라클 공격(Bleichenbacher)에 취약하다.
            Cipher cipher = Cipher.getInstance("RSA");
            cipher.init(Cipher.ENCRYPT_MODE, publicKey);
            // 문제 3: 데이터를 RSA로 직접 암호화한다. RSA는 키 길이보다 짧은 데이터만 처리할 수 있다.
            return cipher.doFinal(data);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] decrypt(PrivateKey privateKey, byte[] data) {
        try {
            Cipher cipher = Cipher.getInstance("RSA");
            cipher.init(Cipher.DECRYPT_MODE, privateKey);
            return cipher.doFinal(data);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }
}
```

| 문제 | 실제로 일어나는 일 (6장 실행 결과) | 이론 |
|---|---|---|
| 1. 1024비트 키 | 보안 강도 약 80비트. 현재 권고(2048 이상)에 못 미친다 | 7-1 |
| 2. `"RSA"` = PKCS#1 v1.5 | 1024비트 키에 117바이트(= 128 - 11)까지만 들어간다. v1.5 암호화 패딩은 패딩 오라클 공격 대상이다 | 함정 2 |
| 3. 데이터를 직접 RSA로 | 1KB를 넣자 `IllegalBlockSizeException: Data must not be longer than 117 bytes` | 함정 1 |

### 3-2. 토큰 헤더를 믿는 JWT 검증기

```java
package com.study.asymmetric;

import java.nio.charset.StandardCharsets;
import java.security.GeneralSecurityException;
import java.security.MessageDigest;
import java.security.PublicKey;
import java.util.Base64;
import java.util.regex.Matcher;

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

/**
 * 토큰 헤더의 alg를 믿고 검증 방법을 고르는 잘못된 검증기. 따라 쓰지 말 것.
 * 과거 여러 JWT 라이브러리가 실제로 이렇게 동작해 취약점(CVE)이 됐다.
 */
public final class BadJwtVerifier {

    private BadJwtVerifier() {
    }

    public static boolean verify(String token, PublicKey publicKey) {
        String[] parts = token.split("\\.", -1);
        if (parts.length != 3) {
            return false;
        }
        String headerJson = new String(Base64.getUrlDecoder().decode(parts[0]), StandardCharsets.UTF_8);
        Matcher m = MiniJwt.ALG.matcher(headerJson);
        String alg = m.find() ? m.group(1) : "";
        byte[] signingInput = (parts[0] + "." + parts[1]).getBytes(StandardCharsets.US_ASCII);
        byte[] sig = Base64.getUrlDecoder().decode(parts[2]);

        switch (alg) {
            case "RS256":
                return Signer.verify("SHA256withRSA", publicKey, signingInput, sig);
            case "HS256":
                // 문제 1: "키"가 공개키 하나뿐이니 그 바이트를 HMAC 비밀로 쓴다.
                //         공개키는 누구나 아므로, 공격자도 똑같이 HMAC 서명을 만들 수 있다.
                return MessageDigest.isEqual(hmac(publicKey.getEncoded(), signingInput), sig);
            case "none":
                // 문제 2: "서명 없음"을 허용한다.
                return true;
            default:
                return false;
        }
    }

    static byte[] hmac(byte[] key, byte[] data) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(key, "HmacSHA256"));
            return mac.doFinal(data);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }
}
```

`switch(alg)`가 자연스러워 보이지만, **검증 방법을 공격자가 고르게 해 준 것**이다. 6장 7번 결과에서 이 검증기는 공개키만으로 위조한 `ADMIN` 토큰을 HS256과 none 두 방식 모두 통과시켰다.

## 4. 개선된 코드

### 1단계: OAEP 파라미터를 전부 고정 — `RsaOaep`

```java
static final OAEPParameterSpec OAEP_SHA256 = new OAEPParameterSpec(
        "SHA-256", "MGF1", MGF1ParameterSpec.SHA256, PSource.PSpecified.DEFAULT);

Cipher cipher = Cipher.getInstance("RSA/ECB/OAEPPadding");
cipher.init(Cipher.ENCRYPT_MODE, publicKey, OAEP_SHA256);
```

- PKCS#1 v1.5 대신 OAEP → **문제 2 해결**
- MGF1 해시까지 명시 → WebCrypto 등 다른 플랫폼과 호환([이론 함정 3](./비대칭키암호화-이론.md#함정-3-oaep-파라미터를-다른-시스템과-맞추지-않았다)). 6장 5번에서 Java 기본값(MGF1 SHA-1)으로 암호화한 값은 MGF1 SHA-256으로 복호화되지 않았다
- 키 길이 3072를 명시 → **문제 1 해결**. JDK 기본값에 기대지 않는다

**남은 문제**: 여전히 318바이트까지만 암호화된다.

### 2단계: 하이브리드 암호화 — `HybridEncryptor`

```java
SecretKey dataKey = KeyGenerator(AES, 256).generateKey();            // 메시지마다 새 키
byte[] wrappedKey = rsa(WRAP_MODE, 공개키, OAEP).wrap(dataKey);         // 32바이트만 RSA로
aes(GCM, dataKey, iv).updateAAD(wrappedKey).doFinal(plaintext);        // 데이터는 AES-GCM
// 출력: [감싼 키 길이 2][감싼 키 384][IV 12][암호문 + 태그 16]
```

- 크기 제한 없음, 1MB 기준 암호화 17ms → **문제 3 해결**
- `Cipher.WRAP_MODE`/`UNWRAP_MODE`는 키 객체를 바로 넘기고 받는 API다. `getEncoded()`로 바이트를 꺼내 `ENCRYPT_MODE`로 암호화해도 결과는 같지만, wrap API를 쓰면 HSM처럼 키 바이트를 꺼낼 수 없는 Provider에서도 동작한다
- 감싼 키를 AAD로 넣었다. 감싼 키를 다른 메시지 것으로 바꿔 끼우면 태그 검증에서 실패한다(테스트 `swapWrappedKey`)

데이터 쪽 AES-GCM은 [대칭키 예제의 `AesGcm`](../대칭키암호화/대칭키암호화-예제.md#5-전체-코드)과 같은 방식이다. 이 예제는 독립 실행을 위해 클래스 안에 직접 썼다.

### 3단계: 서명 — `Signer`

```java
Signature signature = Signature.getInstance(algorithm); // 호출마다 새로. 상태 객체다
signature.initSign(privateKey);
signature.update(data);
return signature.sign();
```

- 알고리즘 문자열만 바꾸면 RSA·ECDSA·Ed25519를 같은 코드로 쓴다
- `verify`에서 `SignatureException`(서명 형식이 깨짐)은 false로, `InvalidKeyException`·`NoSuchAlgorithmException`(설정 오류)은 예외로 구분했다. 설정 오류를 false로 삼키면 장애가 "인증 실패 401"로 숨어 원인을 찾기 어렵다
- ECDSA를 JWT·외부 API와 주고받을 때는 `SHA256withECDSAinP1363Format`을 쓴다([이론 함정 6](./비대칭키암호화-이론.md#함정-6-ecdsa-서명-형식der-vs-p1363이-맞지-않는다))

### 4단계: 키 파일 — `PemKeys`

- `getEncoded()` → PKCS#8(개인키) / X.509(공개키) DER → Base64 64글자 줄바꿈 → BEGIN/END
- 읽을 때 `Base64.getMimeDecoder()`로 `\r\n`을 허용한다(테스트 `crlf`)
- `BEGIN RSA PRIVATE KEY`/`BEGIN EC PRIVATE KEY`는 변환 명령을 담은 메시지로 거부한다. `InvalidKeySpecException`만 보고는 원인을 알기 어렵기 때문이다

Java 8 대체 코드: `String.lines()`는 데모에서만 썼다. `Base64.getMimeEncoder(int, byte[])`와 `getMimeDecoder()`는 Java 8에 있다.

### 5단계: 알고리즘을 고정한 JWT 검증 — `MiniJwt`

```java
Matcher m = ALG.matcher(headerJson);
if (!m.find() || !"RS256".equals(m.group(1))) {
    return false;                               // 헤더의 alg는 "일치 확인"에만 쓴다
}
return Signer.verify("SHA256withRSA", publicKey, signingInput, sig);  // 방법은 서버가 정한다
```

- `BadJwtVerifier`와의 차이는 이 두 줄뿐이다. 검증 방법을 헤더가 아니라 코드가 정한다 → HS256·none 위조가 모두 실패한다
- 서명 대상은 `base64url(header) + "." + base64url(payload)`의 **ASCII 바이트**다. JSON을 다시 직렬화한 바이트가 아니다
- 실무에서는 `exp`·`iss`·`aud` 검증, `kid`로 키 선택, JSON 파싱을 라이브러리가 처리한다. Spring Security의 `NimbusJwtDecoder.withPublicKey(key)`가 이 클래스의 역할을 한다

## 5. 전체 코드

### RsaOaep.java

```java
package com.study.asymmetric;

import java.security.GeneralSecurityException;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.security.spec.MGF1ParameterSpec;

import javax.crypto.Cipher;
import javax.crypto.spec.OAEPParameterSpec;
import javax.crypto.spec.PSource;

/** RSA-OAEP(SHA-256, MGF1-SHA-256). 짧은 비밀(대칭키 등)을 공개키로 감쌀 때만 쓴다. */
public final class RsaOaep {

    // "RSA/ECB/OAEPWithSHA-256AndMGF1Padding"만 쓰면 SunJCE는 MGF1에 SHA-1을 쓴다(실측).
    // 다른 플랫폼은 MGF1도 SHA-256으로 보는 경우가 많아 서로 복호화가 안 된다. 파라미터를 전부 명시한다.
    static final OAEPParameterSpec OAEP_SHA256 = new OAEPParameterSpec(
            "SHA-256", "MGF1", MGF1ParameterSpec.SHA256, PSource.PSpecified.DEFAULT);
    static final String TRANSFORMATION = "RSA/ECB/OAEPPadding"; // ECB는 이름만 있을 뿐 RSA에서는 의미가 없다

    private RsaOaep() {
    }

    public static KeyPair generateKeyPair() {
        try {
            KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA");
            // 기본값은 JDK 버전마다 다르다(실측 JDK 25: 3072). 상대 시스템과 맞추려면 항상 명시한다.
            generator.initialize(3072);
            return generator.generateKeyPair();
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] encrypt(PublicKey publicKey, byte[] data) {
        try {
            Cipher cipher = Cipher.getInstance(TRANSFORMATION);
            cipher.init(Cipher.ENCRYPT_MODE, publicKey, OAEP_SHA256);
            return cipher.doFinal(data);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] decrypt(PrivateKey privateKey, byte[] data) {
        try {
            Cipher cipher = Cipher.getInstance(TRANSFORMATION);
            cipher.init(Cipher.DECRYPT_MODE, privateKey, OAEP_SHA256);
            return cipher.doFinal(data);
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    /** OAEP로 한 번에 암호화할 수 있는 최대 바이트 = 키 바이트 - 2 × 해시 바이트 - 2 */
    public static int maxPlaintextBytes(int keyBits) {
        return keyBits / 8 - 2 * 32 - 2;
    }
}
```

### HybridEncryptor.java

```java
package com.study.asymmetric;

import java.nio.ByteBuffer;
import java.security.GeneralSecurityException;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.security.SecureRandom;

import javax.crypto.AEADBadTagException;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;

/**
 * 하이브리드 암호화: 데이터는 AES-GCM으로, AES 키는 RSA-OAEP로 감싼다.
 * 출력 형식: [감싼 키 길이 2바이트][감싼 키][IV 12바이트][암호문 + 태그 16바이트]
 */
public final class HybridEncryptor {

    private static final SecureRandom RANDOM = new SecureRandom();
    private static final int IV_LENGTH = 12;

    private HybridEncryptor() {
    }

    public static byte[] encrypt(PublicKey recipientPublicKey, byte[] plaintext) {
        try {
            // 1) 메시지마다 새 AES 키(데이터 키). 수신자의 공개키만 있으면 누구나 만들 수 있다.
            KeyGenerator generator = KeyGenerator.getInstance("AES");
            generator.init(256);
            SecretKey dataKey = generator.generateKey();

            // 2) AES 키를 공개키로 감싼다(wrap). RSA가 처리하는 건 32바이트뿐이라 크기 제한에 걸리지 않는다.
            Cipher rsa = Cipher.getInstance(RsaOaep.TRANSFORMATION);
            rsa.init(Cipher.WRAP_MODE, recipientPublicKey, RsaOaep.OAEP_SHA256);
            byte[] wrappedKey = rsa.wrap(dataKey);

            // 3) 실제 데이터는 빠른 AES-GCM으로. 키가 메시지마다 새것이라 IV 충돌 걱정도 사실상 없다.
            byte[] iv = new byte[IV_LENGTH];
            RANDOM.nextBytes(iv);
            Cipher aes = Cipher.getInstance("AES/GCM/NoPadding");
            aes.init(Cipher.ENCRYPT_MODE, dataKey, new GCMParameterSpec(128, iv));
            // 감싼 키를 AAD로 묶어, 다른 메시지의 감싼 키로 바꿔 끼우는 조작을 태그 검증에서 잡는다.
            aes.updateAAD(wrappedKey);
            byte[] body = aes.doFinal(plaintext);

            return ByteBuffer.allocate(2 + wrappedKey.length + IV_LENGTH + body.length)
                    .putShort((short) wrappedKey.length)
                    .put(wrappedKey)
                    .put(iv)
                    .put(body)
                    .array();
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static byte[] decrypt(PrivateKey recipientPrivateKey, byte[] message) {
        try {
            ByteBuffer buf = ByteBuffer.wrap(message);
            int wrappedLength = Short.toUnsignedInt(buf.getShort());
            if (wrappedLength > buf.remaining() - IV_LENGTH - 16) {
                throw new IllegalArgumentException("형식이 잘못된 메시지");
            }
            byte[] wrappedKey = new byte[wrappedLength];
            buf.get(wrappedKey);
            byte[] iv = new byte[IV_LENGTH];
            buf.get(iv);
            byte[] body = new byte[buf.remaining()];
            buf.get(body);

            Cipher rsa = Cipher.getInstance(RsaOaep.TRANSFORMATION);
            rsa.init(Cipher.UNWRAP_MODE, recipientPrivateKey, RsaOaep.OAEP_SHA256);
            SecretKey dataKey = (SecretKey) rsa.unwrap(wrappedKey, "AES", Cipher.SECRET_KEY);

            Cipher aes = Cipher.getInstance("AES/GCM/NoPadding");
            aes.init(Cipher.DECRYPT_MODE, dataKey, new GCMParameterSpec(128, iv));
            aes.updateAAD(wrappedKey);
            return aes.doFinal(body);
        } catch (AEADBadTagException e) {
            throw new IllegalArgumentException("복호화 실패", e);
        } catch (GeneralSecurityException e) {
            // 다른 개인키로 unwrap하면 여기로 온다(OAEP 패딩 검증 실패).
            throw new IllegalArgumentException("복호화 실패", e);
        }
    }
}
```

```java
package com.study.asymmetric;

import java.security.GeneralSecurityException;
import java.security.InvalidKeyException;
import java.security.NoSuchAlgorithmException;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.security.Signature;
import java.security.SignatureException;

/**
 * 전자서명. algorithm 예: "SHA256withRSA", "RSASSA-PSS", "SHA256withECDSA", "Ed25519".
 * Signature도 update로 데이터를 쌓는 상태 객체라서 호출마다 새로 만든다.
 */
public final class Signer {

    private Signer() {
    }

    public static byte[] sign(String algorithm, PrivateKey privateKey, byte[] data) {
        try {
            Signature signature = Signature.getInstance(algorithm);
            signature.initSign(privateKey);
            signature.update(data);
            return signature.sign();
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }

    public static boolean verify(String algorithm, PublicKey publicKey, byte[] data, byte[] sig) {
        try {
            Signature signature = Signature.getInstance(algorithm);
            signature.initVerify(publicKey);
            signature.update(data);
            return signature.verify(sig);
        } catch (SignatureException e) {
            // 서명 형식 자체가 깨진 경우(예: DER이 아닌 바이트). "검증 실패"와 같은 의미로 다룬다.
            return false;
        } catch (NoSuchAlgorithmException | InvalidKeyException e) {
            // 설정 오류는 위조와 구분해서 크게 실패시킨다. false로 삼키면 장애가 "인증 실패"로 숨는다.
            throw new IllegalStateException(e);
        }
    }
}
```

```java
package com.study.asymmetric;

import java.security.GeneralSecurityException;
import java.security.KeyFactory;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.security.spec.PKCS8EncodedKeySpec;
import java.security.spec.X509EncodedKeySpec;
import java.util.Base64;

/**
 * PEM 파일 = "-----BEGIN ...-----" + Base64(DER) + "-----END ...-----".
 * Java 표준 API는 PKCS#8(개인키)과 X.509 SubjectPublicKeyInfo(공개키) DER만 읽는다.
 */
public final class PemKeys {

    private PemKeys() {
    }

    public static String toPem(PublicKey key) {
        // getEncoded()는 X.509 SubjectPublicKeyInfo DER을 돌려준다.
        return wrap("PUBLIC KEY", key.getEncoded());
    }

    public static String toPem(PrivateKey key) {
        // getEncoded()는 PKCS#8 DER을 돌려준다. 이 문자열이 곧 개인키이므로 로그·Git에 남기지 않는다.
        return wrap("PRIVATE KEY", key.getEncoded());
    }

    public static PublicKey readPublicKey(String pem, String algorithm) {
        byte[] der = unwrap(pem, "PUBLIC KEY");
        try {
            return KeyFactory.getInstance(algorithm).generatePublic(new X509EncodedKeySpec(der));
        } catch (GeneralSecurityException e) {
            throw new IllegalArgumentException("공개키를 읽을 수 없다(알고리즘 " + algorithm + ")", e);
        }
    }

    public static PrivateKey readPrivateKey(String pem, String algorithm) {
        if (pem.contains("BEGIN RSA PRIVATE KEY") || pem.contains("BEGIN EC PRIVATE KEY")) {
            // OpenSSL의 전통 형식(PKCS#1 / SEC1)이다. 표준 KeyFactory는 못 읽는다.
            throw new IllegalArgumentException("PKCS#1/SEC1 형식이다. "
                    + "openssl pkcs8 -topk8 -nocrypt -in key.pem -out key-pkcs8.pem 으로 변환해서 쓴다");
        }
        byte[] der = unwrap(pem, "PRIVATE KEY");
        try {
            return KeyFactory.getInstance(algorithm).generatePrivate(new PKCS8EncodedKeySpec(der));
        } catch (GeneralSecurityException e) {
            throw new IllegalArgumentException("개인키를 읽을 수 없다(알고리즘 " + algorithm + ")", e);
        }
    }

    private static String wrap(String type, byte[] der) {
        // PEM은 64글자마다 줄바꿈하는 것이 관례(RFC 7468)라서 MIME 인코더를 쓴다.
        String body = Base64.getMimeEncoder(64, "\n".getBytes()).encodeToString(der);
        return "-----BEGIN " + type + "-----\n" + body + "\n-----END " + type + "-----\n";
    }

    private static byte[] unwrap(String pem, String type) {
        String begin = "-----BEGIN " + type + "-----";
        String end = "-----END " + type + "-----";
        int from = pem.indexOf(begin);
        int to = pem.indexOf(end);
        if (from < 0 || to < 0) {
            throw new IllegalArgumentException(type + " PEM이 아니다");
        }
        String body = pem.substring(from + begin.length(), to);
        // MIME 디코더는 줄바꿈(\r\n 포함)과 공백을 무시한다. 일반 디코더는 예외를 던진다.
        return Base64.getMimeDecoder().decode(body);
    }
}
```

### MiniJwt.java

```java
package com.study.asymmetric;

import java.nio.charset.StandardCharsets;
import java.security.PrivateKey;
import java.security.PublicKey;
import java.util.Base64;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

/**
 * RS256 JWT의 구조를 보여 주기 위한 최소 구현. 실무에서는 Nimbus JOSE + JWT, jjwt 등 검증된 라이브러리를 쓴다.
 * 토큰 = base64url(header) + "." + base64url(payload) + "." + base64url(서명)
 * 서명 대상 = 앞의 두 부분을 "."으로 이은 ASCII 문자열
 */
public final class MiniJwt {

    private static final Base64.Encoder B64URL = Base64.getUrlEncoder().withoutPadding();
    private static final Base64.Decoder B64URL_DEC = Base64.getUrlDecoder();
    static final Pattern ALG = Pattern.compile("\"alg\"\\s*:\\s*\"([^\"]*)\"");

    private MiniJwt() {
    }

    public static String signRs256(String payloadJson, PrivateKey privateKey) {
        String header = B64URL.encodeToString("{\"alg\":\"RS256\",\"typ\":\"JWT\"}".getBytes(StandardCharsets.UTF_8));
        String payload = B64URL.encodeToString(payloadJson.getBytes(StandardCharsets.UTF_8));
        String signingInput = header + "." + payload;
        byte[] sig = Signer.sign("SHA256withRSA", privateKey, signingInput.getBytes(StandardCharsets.US_ASCII));
        return signingInput + "." + B64URL.encodeToString(sig);
    }

    /** 안전한 검증: 알고리즘을 서버 설정으로 고정한다. 헤더의 alg는 "일치하는지 확인"하는 데만 쓴다. */
    public static boolean verifyRs256(String token, PublicKey publicKey) {
        String[] parts = token.split("\\.", -1);
        if (parts.length != 3) {
            return false;
        }
        String headerJson;
        byte[] sig;
        try {
            headerJson = new String(B64URL_DEC.decode(parts[0]), StandardCharsets.UTF_8);
            sig = B64URL_DEC.decode(parts[2]);
        } catch (IllegalArgumentException e) {
            return false;
        }
        Matcher m = ALG.matcher(headerJson);
        if (!m.find() || !"RS256".equals(m.group(1))) {
            return false;
        }
        String signingInput = parts[0] + "." + parts[1];
        return Signer.verify("SHA256withRSA", publicKey, signingInput.getBytes(StandardCharsets.US_ASCII), sig);
    }

    public static String payload(String token) {
        return new String(B64URL_DEC.decode(token.split("\\.")[1]), StandardCharsets.UTF_8);
    }
}
```

```java
    private static void speed(KeyPair rsa, KeyPair ec, KeyPair ed) throws GeneralSecurityException {
        System.out.println("== 9. 속도 (환경마다 다름, 1회당 평균) ==");
        byte[] doc = new byte[256];
        byte[] key32 = new byte[32];
        String[][] ops = {
            {"RSA-3072 서명", "SHA256withRSA"}, {"EC P-256 서명", "SHA256withECDSA"}, {"Ed25519 서명", "Ed25519"}
        };
        KeyPair[] keys = {rsa, ec, ed};
        for (int k = 0; k < ops.length; k++) {
            String alg = ops[k][1];
            KeyPair kp = keys[k];
            byte[] sig = null;
            for (int i = 0; i < 200; i++) {
                sig = Signer.sign(alg, kp.getPrivate(), doc);
                Signer.verify(alg, kp.getPublic(), doc, sig);
            }
            int n = 500;
            long t = System.nanoTime();
            for (int i = 0; i < n; i++) {
                sig = Signer.sign(alg, kp.getPrivate(), doc);
            }
            double signUs = (System.nanoTime() - t) / 1000.0 / n;
            t = System.nanoTime();
            for (int i = 0; i < n; i++) {
                Signer.verify(alg, kp.getPublic(), doc, sig);
            }
            double verifyUs = (System.nanoTime() - t) / 1000.0 / n;
            System.out.printf("%-14s %8.1f µs | 검증 %8.1f µs%n", ops[k][0], signUs, verifyUs);
        }
        byte[] wrapped = RsaOaep.encrypt(rsa.getPublic(), key32);
        for (int i = 0; i < 200; i++) {
            RsaOaep.decrypt(rsa.getPrivate(), RsaOaep.encrypt(rsa.getPublic(), key32));
        }
        int n = 500;
        long t = System.nanoTime();
        for (int i = 0; i < n; i++) {
            RsaOaep.encrypt(rsa.getPublic(), key32);
        }
        double encUs = (System.nanoTime() - t) / 1000.0 / n;
        t = System.nanoTime();
        for (int i = 0; i < n; i++) {
            RsaOaep.decrypt(rsa.getPrivate(), wrapped);
        }
        double decUs = (System.nanoTime() - t) / 1000.0 / n;
        System.out.printf("RSA-3072 OAEP  암호화 %6.1f µs | 복호화 %8.1f µs (32바이트)%n", encUs, decUs);
        t = System.nanoTime();
        KeyPairGenerator g = KeyPairGenerator.getInstance("RSA");
        g.initialize(3072);
        for (int i = 0; i < 5; i++) {
            g.generateKeyPair();
        }
        System.out.printf("RSA-3072 키 쌍 생성 %8.1f ms%n", (System.nanoTime() - t) / 1_000_000.0 / 5);
        System.out.println();
    }

    private static void jdkDefaults() throws GeneralSecurityException {
        System.out.println("== 10. 이 JDK의 기본값 (" + System.getProperty("java.version") + ") ==");
        System.out.println("RSA 기본 키 길이: "
                + ((RSAPublicKey) KeyPairGenerator.getInstance("RSA").generateKeyPair().getPublic()).getModulus().bitLength());
        System.out.println("EC 기본 곡선 크기: "
                + ((ECPublicKey) KeyPairGenerator.getInstance("EC").generateKeyPair().getPublic()).getParams().getCurve().getField().getFieldSize());
        System.out.println("AES 기본 키 길이: " + KeyGenerator.getInstance("AES").generateKey().getEncoded().length * 8);
        try {
            generate("EC", new ECGenParameterSpec("secp256k1"));
        } catch (GeneralSecurityException e) {
            System.out.println("secp256k1 → " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
```

결과 읽기:

- **1번**: 32바이트가 384바이트(키 길이)가 됐다. OAEP는 랜덤이라 같은 평문도 암호문이 다르다.
- **2번**: RSA(PKCS#1 v1.5 서명)와 Ed25519는 같은 문서에 같은 서명을, ECDSA는 매번 다른 서명을 만든다. 모두 위조 문서는 false다.
- **3번**: 1024비트 v1.5는 117바이트, 3072비트 OAEP-SHA256은 318바이트가 한계다. `키 바이트 - 11`, `키 바이트 - 2×32 - 2` 공식과 일치한다.
- **4번**: 1MB를 17ms에 처리했다. RSA는 32바이트 키 하나만 처리하므로 데이터 크기와 무관하게 약 2ms(복호화 시 unwrap)만 더해진다. 다른 개인키로는 unwrap 단계에서 `InvalidKeyException`이 났다.
- **5번**: 이름은 `OAEPWithSHA-256AndMGF1Padding`인데 MGF1은 SHA-1이었다. 그래서 MGF1-SHA256 쪽(WebCrypto 등)과 복호화가 맞지 않는다.
- **6번**: 3072비트 공개키 PEM은 11줄, 개인키 PEM은 40줄이다. `BEGIN RSA PRIVATE KEY`는 변환 안내와 함께 거부됐다.
- **7번**: 핵심 결과다. payload만 바꾼 토큰은 두 검증기 모두 거부했다. 하지만 **`alg`를 바꾼 위조 토큰은 헤더를 믿는 검증기를 통과했다**. 공격자에게 필요한 것은 공개키뿐이었다.
- **8번**: Java 기본 ECDSA 서명은 70·71·72바이트로 길이가 바뀌고, P1363은 항상 64바이트다. 형식이 다르면 검증은 false다.
- **9번**: RSA는 서명(1,780µs)이 검증(43µs)보다 40배 느리다. 개인키 연산(d)과 공개키 연산(e = 65537)의 크기 차이 때문이다. 검증이 많은 JWT에 RSA가 잘 맞는 이유다. RSA-3072 키 생성은 약 0.3초라서 요청마다 키를 만들면 안 된다.
- **10번**: JDK 25의 기본값은 RSA 3072, EC 384, AES 256이다. `secp256k1`은 지원하지 않는다.

```java
package com.study.asymmetric;

import static org.junit.jupiter.api.Assertions.assertArrayEquals;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertInstanceOf;
import static org.junit.jupiter.api.Assertions.assertThrows;
import static org.junit.jupiter.api.Assertions.assertTrue;

import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.spec.ECGenParameterSpec;
import java.util.Arrays;
import java.util.Base64;

import javax.crypto.BadPaddingException;
import javax.crypto.Cipher;
import javax.crypto.IllegalBlockSizeException;

import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Nested;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.TestInstance;

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class AsymmetricTest {

    // RSA 키 생성은 수백 ms가 걸리므로 클래스당 한 번만 만든다.
    private KeyPair rsa;
    private KeyPair otherRsa;
    private KeyPair ec;
    private KeyPair ed;

    @BeforeAll
    void setUp() throws Exception {
        rsa = RsaOaep.generateKeyPair();
        otherRsa = RsaOaep.generateKeyPair();
        KeyPairGenerator g = KeyPairGenerator.getInstance("EC");
        g.initialize(new ECGenParameterSpec("secp256r1"));
        ec = g.generateKeyPair();
        ed = KeyPairGenerator.getInstance("Ed25519").generateKeyPair();
    }

    private static byte[] utf8(String s) {
        return s.getBytes(StandardCharsets.UTF_8);
    }

    @Nested
    @DisplayName("공개키 암호화 (RSA-OAEP)")
    class Encryption {

        @Test
        @DisplayName("공개키로 암호화한 것은 짝이 되는 개인키로만 복호화된다")
        void roundTrip() {
            byte[] ct = RsaOaep.encrypt(rsa.getPublic(), utf8("secret"));
            assertArrayEquals(utf8("secret"), RsaOaep.decrypt(rsa.getPrivate(), ct));
            assertThrows(IllegalStateException.class, () -> RsaOaep.decrypt(otherRsa.getPrivate(), ct));
        }

        @Test
        @DisplayName("OAEP는 랜덤 패딩이라 같은 평문도 암호문이 다르다")
        void randomized() {
            assertFalse(Arrays.equals(RsaOaep.encrypt(rsa.getPublic(), utf8("x")), RsaOaep.encrypt(rsa.getPublic(), utf8("x"))));
        }

        @Test
        @DisplayName("한 번에 암호화할 수 있는 크기는 키 길이로 제한된다 (3072비트 OAEP-SHA256 = 318바이트)")
        void sizeLimit() {
            assertEquals(384, RsaOaep.encrypt(rsa.getPublic(), new byte[318]).length);
            IllegalStateException e = assertThrows(IllegalStateException.class,
                    () -> RsaOaep.encrypt(rsa.getPublic(), new byte[319]));
            assertInstanceOf(IllegalBlockSizeException.class, e.getCause());
        }

        @Test
        @DisplayName("\"RSA\"만 적으면 PKCS#1 v1.5 패딩이다 (1024비트 → 최대 128 - 11 = 117바이트)")
        void defaultIsPkcs1() {
            KeyPair weak = BadRsa.generate();
            assertEquals(128, BadRsa.encrypt(weak.getPublic(), new byte[117]).length);
            assertThrows(IllegalStateException.class, () -> BadRsa.encrypt(weak.getPublic(), new byte[118]));
        }

        @Test
        @DisplayName("SunJCE의 OAEPWithSHA-256AndMGF1Padding은 MGF1에 SHA-1을 쓴다")
        void oaepMgf1Default() throws Exception {
            Cipher c = Cipher.getInstance("RSA/ECB/OAEPWithSHA-256AndMGF1Padding");
            c.init(Cipher.ENCRYPT_MODE, rsa.getPublic());
            byte[] ct = c.doFinal(utf8("hello"));
            IllegalStateException e = assertThrows(IllegalStateException.class, () -> RsaOaep.decrypt(rsa.getPrivate(), ct));
            assertInstanceOf(BadPaddingException.class, e.getCause());
        }
    }

    @Nested
    @DisplayName("하이브리드 암호화")
    class Hybrid {

        private final byte[] data = new byte[100_000];

        @Test
        @DisplayName("크기 제한 없이 암복호화되고, 오버헤드는 2 + 384 + 12 + 16바이트")
        void roundTrip() {
            byte[] msg = HybridEncryptor.encrypt(rsa.getPublic(), data);
            assertEquals(data.length + 414, msg.length);
            assertArrayEquals(data, HybridEncryptor.decrypt(rsa.getPrivate(), msg));
        }

        @Test
        @DisplayName("다른 개인키로는 복호화할 수 없다")
        void wrongKey() {
            byte[] msg = HybridEncryptor.encrypt(rsa.getPublic(), data);
            assertThrows(IllegalArgumentException.class, () -> HybridEncryptor.decrypt(otherRsa.getPrivate(), msg));
        }

        @Test
        @DisplayName("본문 1비트 변조는 GCM 태그에서 걸린다")
        void tamper() {
            byte[] msg = HybridEncryptor.encrypt(rsa.getPublic(), data);
            msg[msg.length - 1] ^= 1;
            assertThrows(IllegalArgumentException.class, () -> HybridEncryptor.decrypt(rsa.getPrivate(), msg));
        }

        @Test
        @DisplayName("다른 메시지의 감싼 키로 바꿔 끼우면 실패한다 (AAD 바인딩)")
        void swapWrappedKey() {
            byte[] m1 = HybridEncryptor.encrypt(rsa.getPublic(), data);
            byte[] m2 = HybridEncryptor.encrypt(rsa.getPublic(), data);
            int keyLen = ByteBuffer.wrap(m1).getShort();
            System.arraycopy(m2, 2, m1, 2, keyLen); // m1에 m2의 감싼 키를 넣는다
            assertThrows(IllegalArgumentException.class, () -> HybridEncryptor.decrypt(rsa.getPrivate(), m1));
        }
    }

    @Nested
    @DisplayName("전자서명")
    class Signatures {

        private final byte[] doc = utf8("{\"orderId\":1001,\"amount\":50000}");
        private final byte[] forged = utf8("{\"orderId\":1001,\"amount\":5}");

        @Test
        @DisplayName("RSA·ECDSA·Ed25519 모두 원본은 통과, 위조 문서·다른 공개키는 실패")
        void verify() {
            Object[][] cases = {{"SHA256withRSA", rsa}, {"SHA256withECDSA", ec}, {"Ed25519", ed}};
            for (Object[] c : cases) {
                String alg = (String) c[0];
                KeyPair kp = (KeyPair) c[1];
                byte[] sig = Signer.sign(alg, kp.getPrivate(), doc);
                assertTrue(Signer.verify(alg, kp.getPublic(), doc, sig), alg);
                assertFalse(Signer.verify(alg, kp.getPublic(), forged, sig), alg);
            }
            byte[] rsaSig = Signer.sign("SHA256withRSA", rsa.getPrivate(), doc);
            assertFalse(Signer.verify("SHA256withRSA", otherRsa.getPublic(), doc, rsaSig));
        }

        @Test
        @DisplayName("RSA PKCS#1 v1.5 서명·Ed25519는 결정적, ECDSA는 매번 다르다")
        void determinism() {
            assertArrayEquals(Signer.sign("SHA256withRSA", rsa.getPrivate(), doc), Signer.sign("SHA256withRSA", rsa.getPrivate(), doc));
            assertArrayEquals(Signer.sign("Ed25519", ed.getPrivate(), doc), Signer.sign("Ed25519", ed.getPrivate(), doc));
            assertFalse(Arrays.equals(Signer.sign("SHA256withECDSA", ec.getPrivate(), doc),
                    Signer.sign("SHA256withECDSA", ec.getPrivate(), doc)));
        }

        @Test
        @DisplayName("ECDSA P1363 형식은 항상 64바이트이고, DER 검증기로는 검증되지 않는다")
        void ecdsaFormats() {
            byte[] raw = Signer.sign("SHA256withECDSAinP1363Format", ec.getPrivate(), doc);
            assertEquals(64, raw.length);
            assertTrue(Signer.verify("SHA256withECDSAinP1363Format", ec.getPublic(), doc, raw));
            assertFalse(Signer.verify("SHA256withECDSA", ec.getPublic(), doc, raw));
        }
    }

    @Nested
    @DisplayName("PEM")
    class Pem {

        @Test
        @DisplayName("PKCS#8 / X.509 PEM으로 저장한 키를 다시 읽어 서명·검증할 수 있다")
        void roundTrip() {
            String pub = PemKeys.toPem(rsa.getPublic());
            String priv = PemKeys.toPem(rsa.getPrivate());
            assertTrue(pub.startsWith("-----BEGIN PUBLIC KEY-----"));
            assertTrue(priv.startsWith("-----BEGIN PRIVATE KEY-----"));
            byte[] sig = Signer.sign("SHA256withRSA", PemKeys.readPrivateKey(priv, "RSA"), utf8("x"));
            assertTrue(Signer.verify("SHA256withRSA", PemKeys.readPublicKey(pub, "RSA"), utf8("x"), sig));
        }

        @Test
        @DisplayName("Windows 줄바꿈(\\r\\n)이 섞여도 읽힌다")
        void crlf() {
            String pub = PemKeys.toPem(ec.getPublic()).replace("\n", "\r\n");
            assertEquals(ec.getPublic(), PemKeys.readPublicKey(pub, "EC"));
        }

        @Test
        @DisplayName("BEGIN RSA PRIVATE KEY(PKCS#1)는 변환 안내와 함께 거부한다")
        void pkcs1Rejected() {
            String pkcs1 = "-----BEGIN RSA PRIVATE KEY-----\nMIIE\n-----END RSA PRIVATE KEY-----\n";
            IllegalArgumentException e = assertThrows(IllegalArgumentException.class, () -> PemKeys.readPrivateKey(pkcs1, "RSA"));
            assertTrue(e.getMessage().contains("openssl pkcs8"));
        }
    }

    @Nested
    @DisplayName("JWT RS256")
    class Jwt {

        private String forgeHs256(String payload) {
            Base64.Encoder enc = Base64.getUrlEncoder().withoutPadding();
            String input = enc.encodeToString(utf8("{\"alg\":\"HS256\",\"typ\":\"JWT\"}")) + "." + enc.encodeToString(utf8(payload));
            return input + "." + enc.encodeToString(BadJwtVerifier.hmac(rsa.getPublic().getEncoded(), input.getBytes(StandardCharsets.US_ASCII)));
        }

        private String forgeNone(String payload) {
            Base64.Encoder enc = Base64.getUrlEncoder().withoutPadding();
            return enc.encodeToString(utf8("{\"alg\":\"none\"}")) + "." + enc.encodeToString(utf8(payload)) + ".";
        }

        @Test
        @DisplayName("정상 토큰은 통과, payload 변조·다른 키는 실패")
        void genuine() {
            String token = MiniJwt.signRs256("{\"sub\":\"user-1\"}", rsa.getPrivate());
            assertTrue(MiniJwt.verifyRs256(token, rsa.getPublic()));
            assertFalse(MiniJwt.verifyRs256(token, otherRsa.getPublic()));
            String[] p = token.split("\\.");
            String tampered = p[0] + "." + Base64.getUrlEncoder().withoutPadding().encodeToString(utf8("{\"sub\":\"admin\"}")) + "." + p[2];
            assertFalse(MiniJwt.verifyRs256(tampered, rsa.getPublic()));
        }

        @Test
        @DisplayName("헤더의 alg를 믿는 검증기는 공개키만으로 위조한 HS256·none 토큰을 통과시킨다")
        void algConfusion() {
            String admin = "{\"sub\":\"user-1\",\"role\":\"ADMIN\"}";
            assertTrue(BadJwtVerifier.verify(forgeHs256(admin), rsa.getPublic()));
            assertTrue(BadJwtVerifier.verify(forgeNone(admin), rsa.getPublic()));
            assertFalse(MiniJwt.verifyRs256(forgeHs256(admin), rsa.getPublic()));
            assertFalse(MiniJwt.verifyRs256(forgeNone(admin), rsa.getPublic()));
        }
    }
}
```

## 8. 변형 실습

1. **`MiniJwt.verifyRs256`에서 `!"RS256".equals(m.group(1))` 조건을 지우면?**
   `algConfusion` 테스트는 여전히 통과한다. 이 검증기는 헤더와 상관없이 항상 RSA로 검증하므로, HS256 위조 서명(32바이트 HMAC)이 RSA 검증에서 실패하기 때문이다. 그렇다면 이 조건은 왜 필요할까? `alg: RS512`처럼 **다른 RSA 알고리즘**으로 서명된 토큰이 들어왔을 때 어떻게 동작해야 하는지, 그리고 "토큰이 주장하는 것과 실제로 검증한 것이 다른 상태"가 로그·감사에서 왜 문제가 되는지 생각해 보자.

2. **`HybridEncryptor`에서 `aes.updateAAD(wrappedKey)` 두 줄을 지우면?**
   `swapWrappedKey` 테스트를 실행해 보자. 다른 메시지의 감싼 키로 바꾸면 **데이터 키 자체가 달라지므로** AAD가 없어도 GCM 태그 검증에서 실패한다. AAD가 실제로 막아 주는 것은 무엇일까? 힌트: 같은 데이터 키를 여러 메시지에 재사용하도록 바꾸거나, 헤더에 "수신자 ID"·"버전" 같은 필드를 추가하는 경우를 생각해 보자. 바인딩하지 않은 헤더 필드는 조작해도 복호화가 성공한다.

3. **ECDSA DER 서명을 P1363(64바이트)으로 직접 변환해 보자.**
   DER 구조는 `30 len 02 lenR R 02 lenS S`다. R·S는 부호 비트 때문에 앞에 `00`이 붙어 33바이트가 되거나, 앞자리가 0이면 31바이트 이하로 줄어든다. 각각을 32바이트로 맞춰 이어 붙이고, `SHA256withECDSAinP1363Format`으로 검증되는지 확인한다. 70·71·72바이트 길이 차이가 어디서 오는지 바이트로 확인할 수 있다. [해시 함정 4](../해시/해시-이론.md#함정-4-같은-값인데-시스템마다-해시가-다르다-인코딩hex-변환)의 "BigInteger가 앞자리 0을 버리는 문제"와 같은 뿌리다.
